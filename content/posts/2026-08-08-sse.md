## 1. 矛盾


知识库聊天有三件彼此拉扯的事：

1. **要快**：用户习惯流式首字，不能等全文生成完再吐。
2. **要可核对**：用了资料就要给来源，否则分不清「库里有」还是「模型在编」。
3. **布局不能抖**：若在流式中途不断往气泡里插引用卡片，高度狂跳，体验比「没引用」更差。

再加上现实里的第三种噪声：部分模型（如 Qwen3）会在 token 流里夹带 think 标签包裹的推理过程——直接展示等于把内部思考泄漏给用户。


本篇解决的是：**检到的 citations，怎样和流式正文共一条协议，又不毁阅读体验。**


## 2. 本篇目标


用 **同一条 UI Message Stream**（Vercel AI SDK / `useChat` 模型）做到：

- 正文按 `text-delta` 流式输出
- 思考链在进 UI 前被增量剥掉
- 文本结束后再追加结构化 `data-citations`
- 前端仅在 `!isStreaming` 时渲染折叠引用区
- 主模型挂了按列表 fallback，错误里带 `requestId`

## 3. 分别解决什么


### 3.1 一条流里其实有三件事


| 关切    | 做法                                                                     | 代码锚点               |
| ----- | ---------------------------------------------------------------------- | ------------------ |
| 流式正文  | `streamText` → `fullStream` 的 `text-delta` 写成 UI `text-*` parts        | `createChatStream` |
| 隐藏思考链 | 每个 delta 过 `ThinkStripFilter.feed`，结束时 `flush`                         | `think-strip.ts`   |
| 可溯源引用 | 正文 `text-end` 之后，若有命中则 `writer.write({ type: "data-citations", ... })` | 同文件流末；前端 `Bubble`  |


对外协议仍是一条 SSE / UI Message Stream：**没有**为引用再开 WebSocket，也**没有**让前端再请求一次「来源 API」。


### 3.2 为什么引用要放在流末，而不是边生成边插？


引用数据在进 `createChatStream` **之前**就已经定了（路由 `retrieve` 且 `getRelevantContext` 成功）：


```typescript
const citations = contextResult.kind === "ok" ? contextResult.citations : [];
const stream = createChatStream({ systemPrompt, messages, requestId, citations });
```


也就是说，服务端其实「早知道」来源。仍然选择流末再写 `data-citations`，是因为 **UI 约束压过「来源可见时间」**：

- 流式过程中插卡片 → 气泡高度随 part 增加而跳，Markdown 重排更晃。
- 用户读的是正在长出来的句子；中途冒出「参考来源」会抢注意力。
- `useChat` 的 message `parts` 是追加模型；流末一次 data part，前端用 `!isStreaming` 门控渲染，状态机简单。

代价很明确：**引用来得比正文略晚**，不适合「边看字边点开某一句的出处」那种交互。Phase 1 选的是「先读完再核对」，不是「逐句锚定」。


### 3.3 为什么思考链要增量剥，而不是全文缓冲后再滤？


若等 `finish` 再对整段做 `replace(/<think>[\s\S]*?<\/think>/g, "")`：

- 首字延迟变成「整段思考 + 整段正文」都生成完才出字
- 长思考时用户只看到转圈

所以用状态机在 **每个 delta** 上工作：标签可能被拆到两个 chunk（例如上一段以 `<thi` 结尾），`carry` + `splitEmitAndPartialTag` 避免把半截标签当正文放出。流结束 `flush`：若仍停在 think 内，剩余全部丢弃（不完整思考块不泄漏）。


### 3.4 为什么模型和引用走同一条流？


| 方案                                 | 结果                                      |
| ---------------------------------- | --------------------------------------- |
| 正文 SSE + 另起 HTTP 拉 citations       | 两次往返、时序要对齐、失败态翻倍                        |
| 正文 WebSocket + 引用事件                | 协议更重，本地/Serverless 都别扭                  |
| **text parts + 流末 data-citations** | 与 AI SDK `useChat` 一致；一个 `requestId` 贯穿 |


原理：citations 是「与本轮助手消息绑定的结构化附件」，语义上就是 message 的一个 part，而不是另一个资源。


### 3.5 优势

1. **体验**：首字仍快；引用区不抖。
2. **协议简单**：前端只懂 `parts`；`data-citations` 是约定好的自定义 type。
3. **与路由对齐**：`direct` / 检索无命中 → `citations=[]` → 不写 data part → UI 无引用区（寒暄不会假装有来源）。
4. **模型韧性**：Groq 上 Qwen → Llama70B → Llama8B 顺序尝试；`maxRetries: 0` 把重试权交给业务 fallback，避免和 SDK 重试缠在一起。
5. **安全体验**：思考链不进 UI；snippet 是纯文本，React 侧不当 HTML 注入。

### 3.6 不做会怎么样


| 若取消…                       | 会发生什么                              |
| -------------------------- | ---------------------------------- |
| **不要引用，只流式文字**             | 无法核对；知识库产品信任破产                     |
| **流式中途插引用**                | 布局跳、难读；`isStreaming` 期间反复 mount 卡片 |
| **另通道拉来源**                 | 竞态（正文完了来源还 404）；多一套错误处理            |
| **不剥 think**               | 用户看见模型内心独白；产品观感像调试台                |
| **全文缓冲再剥 think**           | 首字显著变慢                             |
| **模型失败不 fallback**         | 单模型抖动直接整轮挂；没有 `requestId` 更难排障     |
| **direct 也强行塞假 citations** | 寒暄下出现「参考来源」——比没有更糟                 |


### 3.7 原理小结（对照数据流）


```plain text
decideQueryRoute
  → retrieve? getRelevantContext → citations[]（可能为空）
  → buildSystemPrompt(context)   // 检索块进 system；与 citations 同源不同形态
  → createChatStream({ citations })
       for model in MODELS:
         streamText.fullStream
           text-delta → ThinkStripFilter.feed → text-start/delta
           finish → flush → text-end
         if citations.length → data-citations
         return
       all failed → error(+ requestId)
  → Bubble: 文本始终可渲染；citations 仅 !isStreaming 时取出展示
```


一句话：**流式负责「读得快」，流末 data part 负责「核得着」，过滤器负责「想的过程别露出来」——三件事一条 SSE 做完。**


## 4. 方案取舍（表）


| 方案                                   | 结果             |
| ------------------------------------ | -------------- |
| 流式中途插引用                              | 来源早，布局抖        |
| 另起 WebSocket / 二次 HTTP               | 多协议、多失败态       |
| **正文 text part + 流末 data-citations** | 与 `useChat` 一致 |
| 全文缓冲后再过滤 think                       | 伤首字            |


主模型 fallback：`qwen/qwen3-32b` → `llama-3.3-70b-versatile` → `llama-3.1-8b-instant`。


## 5. 调用链


```plain text
路由 retrieve 且检索 ok → citations
  → createChatStream
       streamText（按模型列表）
         text-delta → ThinkStripFilter → UI text parts
         finish → text-end
       citations 非空 → data-citations
  → 前端 !isStreaming 时渲染折叠引用
direct / no-docs → citations=[] → 无 data part → 无引用区
```


## 6. 关键实现（完整核心）


### 6.1 引用数据结构


检索命中映射为前端卡片（snippet 截断，避免气泡爆炸）：


```typescript
export interface Citation {
  documentId: string;
  title: string;
  /** 0–1，前端可显示为百分比 */
  similarity: number;
  snippet: string;
  source?: string;
  category?: string;
  chunkIndex?: number;
}

const SNIPPET_MAX_LENGTH = 280;

export function mapDocsToCitations(
  docs: {
    documentId?: string;
    title?: string;
    $similarity?: number;
    content: string;
    source?: string;
    category?: string;
    chunkIndex?: number;
  }[],
): Citation[] {
  return docs.map((doc, index) => ({
    documentId: doc.documentId ?? `unknown-${index}`,
    title: doc.title ?? "未命名文档",
    similarity: doc.$similarity ?? 0,
    snippet:
      doc.content.length > SNIPPET_MAX_LENGTH
        ? `${doc.content.slice(0, SNIPPET_MAX_LENGTH)}…`
        : doc.content,
    source: doc.source,
    category: doc.category,
    chunkIndex: doc.chunkIndex,
  }));
}
```


进模型的 context 与进 UI 的 citations **同源**：前者包进 `<context trusted="false">` 供生成，后者给用户核对。两套形态，一次检索。


### 6.2 思考链过滤器（跨 chunk 安全）


```typescript
const OPEN_TAG = "<" + "think" + ">";
const CLOSE_TAG = "<" + "/" + "think" + ">";

/** 避免标签被拆到两个 delta 时误放出 */
function splitEmitAndPartialTag(text: string, tag: string): { emit: string; keep: string } {
  for (let len = Math.min(text.length, tag.length - 1); len >= 1; len--) {
    const suffix = text.slice(-len);
    if (tag.startsWith(suffix)) {
      return { emit: text.slice(0, -len), keep: suffix };
    }
  }
  return { emit: text, keep: "" };
}

export class ThinkStripFilter {
  private inThink = false;
  private carry = "";

  feed(delta: string): string {
    this.carry += delta;
    let out = "";

    while (this.carry.length > 0) {
      if (this.inThink) {
        const closeIdx = this.carry.indexOf(CLOSE_TAG);
        if (closeIdx === -1) {
          this.carry = splitEmitAndPartialTag(this.carry, CLOSE_TAG).keep;
          break;
        }
        this.carry = this.carry.slice(closeIdx + CLOSE_TAG.length).replace(/^\s+/, "");
        this.inThink = false;
        continue;
      }

      const openIdx = this.carry.indexOf(OPEN_TAG);
      if (openIdx === -1) {
        const { emit, keep } = splitEmitAndPartialTag(this.carry, OPEN_TAG);
        out += emit;
        this.carry = keep;
        break;
      }

      out += this.carry.slice(0, openIdx);
      this.carry = this.carry.slice(openIdx + OPEN_TAG.length);
      this.inThink = true;
    }
    return out;
  }

  flush(): string {
    if (this.inThink) {
      this.carry = "";
      this.inThink = false;
      return ""; // 未闭合的思考块：整段丢弃，不泄漏
    }
    const rest = this.carry;
    this.carry = "";
    return rest;
  }
}
```


### 6.3 流式生成 + 流末 citations


```typescript
import { streamText, createUIMessageStream } from "ai";

const MODELS = [
  "qwen/qwen3-32b",
  "llama-3.3-70b-versatile",
  "llama-3.1-8b-instant",
] as const;

export function createChatStream(options: {
  systemPrompt: string;
  messages: { role: "user" | "assistant"; content: string }[];
  requestId: string;
  citations?: Citation[];
  chatModel: (modelId: string) => unknown;
  log?: { warn: (m: string, meta?: object) => void; error: (m: string, meta?: object) => void };
}) {
  const { systemPrompt, messages, requestId, citations = [], chatModel, log } = options;

  return createUIMessageStream({
    execute: async ({ writer }) => {
      const messageId = `msg-${Date.now()}`;
      let hasStarted = false;
      let lastError: Error | null = null;

      for (const modelName of MODELS) {
        try {
          const result = streamText({
            model: chatModel(modelName) as any,
            system: systemPrompt,
            messages,
            temperature: 0.7,
            maxRetries: 0, // 重试交给外层模型列表，避免双重重试
          });

          const thinkFilter = new ThinkStripFilter();

          for await (const part of result.fullStream) {
            if (part.type === "text-delta") {
              const visible = thinkFilter.feed(part.text);
              if (!visible) continue;
              if (!hasStarted) {
                writer.write({ type: "text-start", id: messageId });
                hasStarted = true;
              }
              writer.write({ type: "text-delta", delta: visible, id: messageId });
            } else if (part.type === "finish") {
              const trailing = thinkFilter.flush();
              if (trailing) {
                if (!hasStarted) {
                  writer.write({ type: "text-start", id: messageId });
                  hasStarted = true;
                }
                writer.write({ type: "text-delta", delta: trailing, id: messageId });
              }
              if (hasStarted) {
                writer.write({ type: "text-end", id: messageId });
              }
            } else if (part.type === "error") {
              throw part.error;
            }
          }

          // 正文结束后再推引用，避免流式过程布局跳动
          if (citations.length > 0) {
            writer.write({
              type: "data-citations",
              id: `citations-${messageId}`,
              data: { citations },
            });
          }
          return;
        } catch (error) {
          log?.warn("model failed, falling back", { modelName, err: error });
          lastError = error instanceof Error ? error : new Error(String(error));
          // 尝试下一模型
        }
      }

      log?.error("all models failed", { err: lastError });
      writer.write({
        type: "error",
        errorText: `服务暂时不可用，请稍后重试 (requestId: ${requestId})`,
      });
    },
  });
}
```


### 6.4 前端消费


```typescript
function extractCitations(message: UIMessage): Citation[] {
  for (const part of message.parts) {
    if (
      part.type === "data-citations" &&
      "data" in part &&
      part.data &&
      typeof part.data === "object" &&
      "citations" in part.data &&
      Array.isArray((part.data as { citations: unknown }).citations)
    ) {
      return (part.data as { citations: Citation[] }).citations;
    }
  }
  return [];
}

function Bubble({ message, isStreaming = false }: { message: UIMessage; isStreaming?: boolean }) {
  const content = message.parts
    .filter((p) => p.type === "text" && "text" in p)
    .map((p) => ("text" in p ? String(p.text) : ""))
    .join("");

  // 流式未结束不展示引用，避免高度跳动
  const citations =
    message.role === "assistant" && !isStreaming ? extractCitations(message) : [];

  if (!content) return null;

  return (
    <div className={message.role === "assistant" ? "message-assistant" : "message-user"}>
      {/* Markdown 渲染正文 ... */}
      {citations.length > 0 && <CitationCards citations={citations} />}
    </div>
  );
}

function CitationCards({ citations }: { citations: Citation[] }) {
  return (
    <details>
      <summary>参考来源（{citations.length}）</summary>
      {citations.map((c) => (
        <div key={`${c.documentId}-${c.chunkIndex ?? 0}`}>
          <strong>{c.title}</strong>
          <span>{Math.round(c.similarity * 100)}%</span>
          <p>{c.snippet}</p>
        </div>
      ))}
    </details>
  );
}
```

```typescript
// 全部失败

```

| 字段                      | 用途                             |
| ----------------------- | ------------------------------ |
| `citationsCount`        | 本轮是否附带引用、附带几条                  |
| `ttftMs`                | 首个可见 text-delta 时间（剥 think 之后） |
| `modelName`（成功那次）       | fallback 是否经常落到 8B             |
| `thinkStripped`（布尔或字节数） | 思考链过滤是否在干活                     |


引用「对不对」不在本层判；那是检索 / 双路的指标（下一篇）。本层只保证：**该送的 data part 送到了，不该送的（空数组）没写。**


## 8. 如何验证

1. 知识类且检索命中：流式过程无引用区；结束后出现折叠「参考来源」。
2. 寒暄 / 路由 direct：始终无引用区。
3. 检索 `no-docs`：有回答，无引用区。
4. 模型输出含 think 标签：UI 只见正文。
5. 跨 chunk 切开标签（单测 `ThinkStripFilter`）：不泄漏半截标记。
6. 弄挂前两个模型：落到下一模型；全挂则错误含 `requestId`。

## 9. 边界

- 引用来得晚，不做逐句高亮锚定。
- `data-citations` 只保证送达；命中质量取决于检索与路由（第 2、4 篇）。
- Think 过滤按字面标签匹配；模型若换另一种思考标记，要加规则。
- Fallback 列表写死在配置/常量里，不是按地区或负载动态选模。
- 流式中途用户刷新：可能只看到部分正文、看不到尚未写出的 data part——刷新后历史若未持久化，本轮引用会丢（Phase 1 无聊天历史库）。
- system 里的 `<context>` 与 UI citations 同源，但用户看不见 context 标签本身；若生成「编造了卡片上没有的细节」，卡片只能辅助核对，不能形式化证明忠实。

## 10. 收束


流式聊天与可溯源引用可以共一条协议流：

1. **为什么流末引用**：早知道来源，但晚展示，是为了布局与阅读。
2. **为什么增量剥 think**：保 TTFT，且防跨 chunk 泄漏。
3. **为什么一条 SSE**：citations 是本轮消息的结构化 part，不是第二个 API。
4. **和路由的关系**：没检到就空数组，UI 自然无卡片。

事后一句话：**没有另起通道，而是把引用做成流末的一次结构化事件；把思考留在模型侧，把句子先交给用户。**
