> **Personal GPT Phase 2 · 系列第 12 篇** 

## 0. 背景


**为什么「让模型跑一段 JS」很危险？**


大模型生成的字符串若直接丢进 `eval`、`new Function`、`vm.runInNewContext`，等于在你的服务器上执行**攻击者可间接控制的代码**：读环境变量、扫文件系统、打内网、挖矿。沙箱（如 QuickJS / isolated-vm）能降低风险，但引入原生依赖、逃逸面与运维复杂度——而 Analyst 只需要 **四则运算**。


**本工具做什么？**


`calculator` 只接受数字与 `+ - * / ()`。先用正则白名单，再**手写递归下降解析器**求值。没有 JS 运行时，没有 `require`。


**MVP 关账（白话）**：本阶段以「演示与回归能过」为收工标准，不是「通用沙箱平台」或生产完备。少一个运行时，就少一类 CVE 追踪。


**递归下降（白话）**：按语法一层层吃掉表达式（先括号、再乘除、再加减），而不是把字符串丢进 JS 引擎。失败模式是「拒绝解析」，不是「偶然执行成功」。

## 1. 开场矛盾


Analyst 需要算「(营收 - 成本) / 人数」这类式子。三条路都诱人：

1. **`eval(expr)`**：三行搞定，安全事故也三行搞定。
2. **QuickJS / WASM 沙箱**：看起来「工业级」，依赖重、边界仍要盯逃逸与资源耗尽。
3. **手写算术解析**：丑一点，但攻击面收缩到「表达式语言」本身。

Phase 2 的产品边界是：**可演示的数值辅助，不是通用代码执行器。** 我们选了第 3 条，并在代码注释里写死「无 eval / vm / QuickJS」。


## 2. 本篇目标


讲清 `calculator` 工具：`SAFE_EXPR`、`FORBIDDEN`、tokenize、`parseExpression`、长度与括号深度上限，以及为何拒绝 QuickJS。


## 3. 受限计算器


### 3.1 总览


| 层/部件               | 做什么          | 代价           | 代码入口 |
| ------------------ | ------------ | ------------ | ---- |
| `SAFE_EXPR`        | 字符级白名单       | 不支持函数、变量、幂运算 | §6   |
| `FORBIDDEN`        | 危险标识符拒绝      | 依赖词表         | §6   |
| `tokenize`         | 切数字与运算符      | 非法字符立即失败     | §6   |
| `parseExpression`  | 递归下降求值       | 手写优先级        | §6   |
| `invokeCalculator` | 捕获错误 → 中文拒绝句 | 模型需改写表达式     | §6   |


语法（直觉）：


```plain text
expr   = term (("+" | "-") term)*
term   = factor (("*" | "/") factor)*
factor = number | "(" expr ")" | "+" factor | "-" factor
```


### 3.2 为什么不用 QuickJS / eval


| 方案             | 真实代价                                          |
| -------------- | --------------------------------------------- |
| `eval` / `vm`  | 经典 RCE；`process`、原型污染、超时难彻底                   |
| QuickJS 嵌入     | native/WASM 供应链、内存上限、宿主桥接 API 一开又变宽；对「加减乘除」过重 |
| 表达式 DSL + 递归下降 | 只实现需要的语义；失败模式是「拒绝」，不是「偶然执行成功」                 |


MVP 关账标准是演示与回归，不是「通用沙箱平台」。少一个运行时，就少一类 CVE 追踪。


### 3.3 优势


| 对比对象        | 本方案优势               |
| ----------- | ------------------- |
| 让模型心算       | 大数 / 多步式子易错；工具结果可核对 |
| eval        | 无代码执行面              |
| QuickJS     | 无原生依赖；行为完全由 TS 单测钉死 |
| 支持任意 JS 数学库 | 攻击面与版本漂移；本阶段不需要     |


### 3.4 不做会怎么样


| 若取消…            | 会发生什么                     |
| --------------- | ------------------------- |
| 取消 `SAFE_EXPR`  | 字母与符号进入解析器，行为难料           |
| 取消 `FORBIDDEN`  | 仅白名单时，未来若放宽字符集会瞬间变险       |
| 改用 `eval`       | 服务器 RCE；密钥与数据可被读走         |
| 引入 QuickJS「图省事」 | 依赖膨胀；仍要做资源限制与桥接审计         |
| 取消除零 / 非有限数检查   | `Infinity` / `NaN` 污染后续报告 |
| 取消长度 / 深度上限     | 恶意超深括号打爆栈或 CPU            |


### 3.5 原理小结


```plain text
expression
  → trim；长度 ≤ 200
  → FORBIDDEN 或 !SAFE_EXPR → throw
  → 括号深度 ≤ 32
  → tokenize → parseExpression
  → Number.isFinite ? 返回 : throw
  → invokeCalculator 包一层中文错误，不抛穿图
```


一句话原理：**把「执行代码」降级成「解析算术 AST」，危险能力根本不存在。**


## 4. 方案取舍


| 方案                    | 优点         | 缺点 / 为何不选               |
| --------------------- | ---------- | ----------------------- |
| `mathjs` 等表达式库        | 功能多        | 依赖面大；历史也曾有过解析器漏洞叙事，需持续跟 |
| QuickJS / isolated-vm | 可跑更复杂脚本    | Phase 2 明确不做；运维与逃逸成本高   |
| 仅正则替换算数               | 短          | 优先级 / 括号难正确             |
| **手写递归下降（采用）**        | 可控、可单测、零原生 | 不支持 `**`、函数、变量          |


## 5. 调用链


```plain text
Analyst 决定调用 calculator
  → tool({ expression })
  → invokeCalculator
  → evaluateSafeArithmetic
  → 成功：「计算结果: N」
  → 失败：「拒绝：表达式非法或不安全…」
  → 文本回到消息流，供 Editor / Supervisor 综合
```


## 6. 关键实现（完整核心）


以下为仓库中计算器工具的完整控制流（与实现一致）：


```typescript
/**
 * calculator：受限算术求值（无 eval / vm / QuickJS）
 */

import { tool } from "langchain";
import { z } from "zod";

// 字符白名单：只允许数字、空格、四则运算符与括号
const SAFE_EXPR = /^[\d\s+\-*/().]+$/;
// 即便字符集过关，仍拒绝常见 JS / 宿主危险标识符
const FORBIDDEN = /\b(require|process|global|Function|eval|import|export|window|document)\b/i;

/** 词法分析：把字符串切成数字 token 与运算符 token */
function tokenize(expr: string): string[] {
  const tokens: string[] = [];
  let i = 0;
  while (i < expr.length) {
    const ch = expr[i]!;
    if (/\s/.test(ch)) {
      i += 1;
      continue;
    }
    if ("+-*/()".includes(ch)) {
      tokens.push(ch);
      i += 1;
      continue;
    }
    if (/\d|\./.test(ch)) {
      let j = i + 1;
      while (j < expr.length && /[\d.]/.test(expr[j]!)) j += 1;
      tokens.push(expr.slice(i, j)); // 连续数字/小数点合并为一个 number token
      i = j;
      continue;
    }
    throw new Error(`非法字符:${ch}`);
  }
  return tokens;
}

/** 递归下降：expr → term ((+|-) term)*；term → factor ((*|/) factor)*；factor → number | (expr) | unary+/- */
function parseExpression(tokens: string[]): number {
  let pos = 0;

  function peek(): string | undefined {
    return tokens[pos];
  }

  function consume(expected?: string): string {
    const t = tokens[pos];
    if (t === undefined) {
      throw new Error("表达式不完整");
    }
    if (expected !== undefined && t !== expected) {
      throw new Error(`期望${expected}，得到${t}`);
    }
    pos += 1;
    return t;
  }

  function parseExpr(): number {
    let left = parseTerm(); // 最低优先级：加减
    while (peek() === "+" || peek() === "-") {
      const op = consume();
      const right = parseTerm();
      left = op === "+" ? left + right : left - right;
    }
    return left;
  }

  function parseTerm(): number {
    let left = parseFactor(); // 较高优先级：乘除（先于加减结合）
    while (peek() === "*" || peek() === "/") {
      const op = consume();
      const right = parseFactor();
      if (op === "/") {
        if (right === 0) throw new Error("除零"); // 显式拒绝，避免 Infinity 污染报告
        left = left / right;
      } else {
        left = left * right;
      }
    }
    return left;
  }

  function parseFactor(): number {
    if (peek() === "+") {
      consume("+");
      return parseFactor(); // 一元正号
    }
    if (peek() === "-") {
      consume("-");
      return -parseFactor(); // 一元负号
    }
    if (peek() === "(") {
      consume("(");
      const v = parseExpr(); // 括号内递归回到 expr 层
      consume(")");
      return v;
    }
    const raw = consume();
    if (!/^\d+(\.\d+)?$/.test(raw)) {
      throw new Error(`非法数字:${raw}`);
    }
    return Number(raw);
  }

  const value = parseExpr();
  if (pos !== tokens.length) {
    throw new Error("多余的 token"); // 如 "1 2" 未消费完
  }
  return value;
}

/** 入口：先护栏校验，再 tokenize → parseExpression 求值 */
export function evaluateSafeArithmetic(expression: string): number {
  const trimmed = expression.trim();
  if (!trimmed) {
    throw new Error("空表达式");
  }
  const MAX_EXPR_LEN = 200;
  const MAX_DEPTH = 32;
  if (trimmed.length > MAX_EXPR_LEN) {
    throw new Error("表达式过长"); // 防超长输入耗 CPU
  }
  if (FORBIDDEN.test(trimmed) || !SAFE_EXPR.test(trimmed)) {
    throw new Error("不安全或不支持的表达式");
  }
  let depth = 0;
  let maxDepth = 0;
  for (const ch of trimmed) {
    if (ch === "(") {
      depth += 1;
      maxDepth = Math.max(maxDepth, depth);
    } else if (ch === ")") {
      depth -= 1;
    }
  }
  if (maxDepth > MAX_DEPTH) {
    throw new Error("括号嵌套过深"); // 防恶意深嵌套打爆递归栈
  }
  const value = parseExpression(tokenize(trimmed));
  if (!Number.isFinite(value)) {
    throw new Error("计算结果非有限数"); // 兜底 NaN / Infinity
  }
  return value;
}

/** LangChain 工具入口：失败不抛穿图，统一返回中文拒绝句 */
export async function invokeCalculator(input: { expression: string }): Promise<string> {
  try {
    const value = evaluateSafeArithmetic(input.expression);
    return `计算结果:${value}`;
  } catch {
    return "拒绝：表达式非法或不安全（仅支持数字与 + - * / ()）。请改用安全算术表达式。";
  }
}

export const calculatorTool = tool(
  async (input: { expression: string }) => invokeCalculator(input),
  {
    name: "calculator",
    description: "安全算术计算器。仅支持数字与 + - * / 括号；禁止代码或系统调用。",
    schema: z.object({
      expression: z.string().min(1).describe("算术表达式，例如 (10 - 4) / 2"),
    }),
  },
);
```

## 9. 诚实边界

- **不支持**幂、开方、变量、百分比符号、千分位逗号。模型若生成 `2^3` 会被拒绝。
- 白名单是字符级，不是形式化安全证明；仍靠长度 / 深度护栏。
- `invokeCalculator` 吞掉具体错误信息，便于安全，但调试时要靠单测而非生产日志细节。
- QuickJS / 办事型工具（改日历等）在路线图里标为**不做进 v2**。
- 这不是「模型代码解释器」产品。

## 10. 收束

1. 「让模型跑 JS」把助手变成远程代码执行面。
2. Analyst 只需要算术，不需要通用运行时。
3. 白名单 + 递归下降把能力钉死在四则运算。
4. 拒绝 QuickJS 是复杂度与攻击面的主动取舍，不是「还没来得及接」。
5. 计算器篇是护栏专题之一；下一篇讲 LangSmith fail-open。整体仍是：可演示、有护栏、诚实降级——不是生产完备。
