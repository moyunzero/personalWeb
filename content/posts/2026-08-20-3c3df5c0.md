> **Personal GPT Phase 2 · 系列第 8 篇**

## 0. 背景


**长任务为什么要进度？**


Agent 模式可能连续跑「查库 → 联网 → 写报告」。中间几十秒只有转圈时，用户分不清是「还在干活」还是「挂了」。待办清单和步骤条把等待变成**可解释的过程**。


**SSE 与 data part**


浏览器和服务器之间用 **SSE（Server-Sent Events）** 一条长连接「直播」结果。除了正文的字（`text-delta`），还可以塞结构化附件，叫 **data part**——例如 `data-todo-update`、`data-agent-step`、`data-agent-trace`。前端读 `message.parts`，不必再开第二条接口。


**执行轨迹 ≠ 模型内心独白**


轨迹记录的是产品可观测事件：路由意图、待办、哪位专科、调了什么工具、引用、终稿、错误。它不是 CoT（思维链 / Chain-of-Thought），也不会把 `<think>` 泄漏给用户。


**指纹去重（fingerprint）**：把「同一类工具噪声」压成一条轨迹事件。例如多次 `kb_search` 的 `NO_RELEVANT_HIT` 会共享同一指纹键，避免时间线被同一 miss 刷屏；代价是你在面板上可能看不到「试了三路 query」的每一次。


**fail-open（再提）**：可选落盘 / LangSmith 挂了，不应让用户主 SSE 挂掉——轨迹是加速排障，不是电源开关。


---


## 1. 开场矛盾


多专科跑通之后，验收卡在体验层：

1. **只有转圈**：用户不知道现在是 Retriever 还是 Researcher，超时还是正常慢。
2. **步骤有了、无法复盘**：演示结束只剩终稿；评测「谁漏跑了」只能猜。
3. **轨迹太吵**：同一 `kb_search` miss 被记十几次，时间线刷屏。

矛盾很具体：**过程可见是产品需求，但「可见」若变成噪音或第二套调试协议，反而拖垮演示。**


## 2. 本篇目标


讲清三层 UI 数据：`data-todo-update` / `data-agent-step` / `data-agent-trace`，以及服务端 `createAgentTraceCollector`（事件种类、上限 200、工具指纹去重、可选落盘）与前端 `extractAgentTrace` + MD/JSON 下载。


不负责 Sequential 边（第 1 篇）、流式消毒（第 2 篇）、联网配额（第 9 篇）。


§3 先讲清「为什么 / 优势 / 不做会怎样 / 原理」；后文给完整代码与边界。


## 3. 进度与轨迹


### 3.1 总览


| 层/部件                                                    | 做什么                            | 代价            | 代码入口           |
| ------------------------------------------------------- | ------------------------------ | ------------- | -------------- |
| `writeProgress`                                         | 写出 todos + steps 两条 data 协议    | 前端要认 type     | §6.1           |
| `createProgressTracker`                                 | 随专科更新 pending/active/completed | 状态机在服务端       | agent.service  |
| `createAgentTraceCollector`                             | 收集 intent→…→final/error        | 内存事件上限 200    | §6.2           |
| `data-agent-trace`                                      | 流末一次写入完整文档                     | 须在 `start` 之后 | streamChat     |
| `AgentTodoList` / `AgentStepPanels` / `AgentTracePanel` | 从 parts 提取并渲染                  | 仅 Agent 模式气泡  | web components |


事件 `kind`（代码枚举）：


| kind           | 含义          |
| -------------- | ----------- |
| `intent`       | 路由与强制专科清单   |
| `plan`         | 待办快照        |
| `specialist`   | 某专科开始/产出摘要  |
| `tool`         | 工具调用（带指纹去重） |
| `intermediate` | 专科中间文本摘要    |
| `citation`     | 结构化引用       |
| `final`        | 终稿摘要        |
| `error`        | 错误          |


### 3.2 为什么要这么做

- **信任不对称**：长任务失败时，用户宁可看到「联网超时已跳过」，也不愿干等后看到空白。
- **验收证据**：Phase 2 关账要「浏览器能看见步骤 / 轨迹」，不是 KPI 盘；SSE data part 正好当证据载体。
- **复盘与演示分离**：UI 时间线给人看；`AGENT_TRACE_PERSIST=true` 时落盘 `.data/agent-traces/`（JSON + Markdown）给评测。

### 3.3 优势


| 对比对象                | 本方案优势                          |
| ------------------- | ------------------------------ |
| 只打 console.log      | 演示用户看不见；关账无法截图验收               |
| 另开 WebSocket 推进度    | 多一套协议与鉴权；与 AI SDK `useChat` 脱节 |
| 无上限、无去重的全量事件        | 时间线爆炸；重复 miss 淹没真实错误           |
| 仅 Markdown 终稿里写「步骤」 | 流式过程中不可见；无法下载结构化 JSON          |


### 3.4 不做会怎么样


| 若取消…                      | 会发生什么                     |
| ------------------------- | ------------------------- |
| 取消 `data-todo-update`     | 多步任务看起来像「黑盒生成」            |
| 取消 `data-agent-step`      | 无法标「谁在干活」；短路步骤也没面板        |
| 取消 `TRACE_EVENTS_MAX=200` | 长跑内存与 SSE 体积失控            |
| 取消工具指纹去重                  | 同一 NO_HIT 刷屏，轨迹不可读        |
| 取消流末 `data-agent-trace`   | 演示后无法下载复盘；验收缺证据           |
| 在 `start` 之前写 data-*      | `useChat` 可能拆成两条助手消息（已踩坑） |


### 3.5 原理小结（数据流）


```plain text
streamChat
  → createAgentTraceCollector（首条 intent）
  → writer.write(start)          ← 必须先 start
  → writeProgress(todos, steps)  ← data-todo-update + data-agent-step*
  → 图运行中：tracker 更新 → writeProgress；trace.record*
  → emitTrace:
       finish() → 可选 persistIfEnabled()
       → writer.write(data-agent-trace)
  → 前端 extractTodos / extractAgentSteps / extractAgentTrace
```


一句话原理：**进度是直播字幕；轨迹是事后剧本；都挂在同一条 UIMessage 的 parts 上。**


## 4. 方案取舍


| 方案                            | 优点              | 缺点 / 为何不选                |
| ----------------------------- | --------------- | ------------------------ |
| 前端轮询 `/agent/status`          | 实现直观            | 多请求、难与消息绑定、Serverless 别扭 |
| LangSmith 当唯一 UI              | 工程观测强           | 密钥与产品 UI 不应绑第三方控制台       |
| **SSE data parts + 可选落盘（采用）** | 与 Chat 引用卡片同一模型 | 要管上限、去重、start 顺序         |


为何不在建图时就 `persist`：任务未结束没有 `final`；落盘放在 `finish` / `persistIfEnabled`，默认关闭（`AGENT_TRACE_PERSIST !== "true"` 直接 return null）。


## 5. 调用链


```plain text
用户发多步问题（Agent 模式）
  → BFF → agent-service streamChat
  → buildInitialProgress → writeProgress
  → Sequential/Supervisor 推进专科
       → ProgressTracker 改 status → writeProgress
       → recordTool / recordSpecialist / …
  → 流结束 emitTrace → data-agent-trace
  → Bubble：AgentTodoList + AgentStepPanels +（流结束后）AgentTracePanel
  → 可选：下载 MD/JSON；服务端 AGENT_TRACE_PERSIST=true 写磁盘
```


## 6. 关键实现（完整核心）

> §6.2 的 `toMarkdown()` 在文中是**节选**（突出时间线结构）；仓库实现还会写入 startedAt/endedAt、待办、detail fence、引用与终稿截断等。下载按钮应以 `apps/web` 侧实际导出为准。

### 6.1 写出进度 data parts


```typescript
/** 待办项：多步任务顶部的 checklist */
type TodoItem = {
  id: string;
  label: string;
  status: "pending" | "active" | "completed";
};

/** 专科步骤：标「谁在干活、进行到哪」 */
type AgentStepPayload = {
  id: string;
  agent: string;
  title: string;
  status: "pending" | "active" | "completed" | "error";
  summary?: string;
};

/** 往 SSE 流写进度 data part，前端从 message.parts 提取 */
function writeProgress(
  writer: { write: (chunk: unknown) => void },
  threadId: string,
  todos: TodoItem[],
  steps: AgentStepPayload[],
): void {
  // 始终写出 todos（含空数组），以便直答时清掉前端残留的调研待办
  writer.write({
    type: "data-todo-update",
    id: `todo-${threadId}`,
    data: { todos },
  });
  // 每个专科步骤单独一条 data-agent-step
  for (const step of steps) {
    writer.write({
      type: "data-agent-step",
      id: step.id,
      data: step,
    });
  }
}
```


### 6.2 轨迹收集器（上限、去重、落盘）


```typescript
import { mkdirSync, writeFileSync } from "node:fs";
import { resolve } from "node:path";

// 轨迹字段截断与事件上限，防止长跑内存/SSE 体积失控
export const TRACE_DETAIL_MAX = 2000;
export const TRACE_FINAL_MAX = 8000;
export const TRACE_EVENTS_MAX = 200;

export type AgentTraceEventKind =
  | "intent"
  | "plan"
  | "specialist"
  | "tool"
  | "intermediate"
  | "citation"
  | "final"
  | "error";

/** 截断 detail/final 文本，轨迹是摘要级观测非完整回放 */
export function truncateTraceText(text: string, max = TRACE_DETAIL_MAX): string {
  const t = text.trim();
  if (t.length <= max) return t;
  return `${t.slice(0, max)}…`;
}

/** 把 threadId 洗成安全文件名，防路径穿越 */
function sanitizeTracePathSegment(raw: string): string {
  const cleaned = raw
    .replace(/\.\./g, "_")
    .replace(/[^A-Za-z0-9_.:-]/g, "_")
    .slice(0, 128);
  return cleaned || "thread";
}

function nowIso(): string {
  return new Date().toISOString();
}

/** 每次 streamChat 创建一个收集器，流末产出完整轨迹文档 */
export function createAgentTraceCollector(input: {
  threadId: string;
  userText: string;
  intent: { route: string; requiredSpecialists: string[] };
  langsmithProject?: string;
}) {
  const startedAt = nowIso();
  // 按时间追加的可观测事件；plan/citations/finalText 单独维护
  const events: Array<{
    ts: string;
    kind: AgentTraceEventKind;
    summary: string;
    name?: string;
    agent?: string;
    detail?: string;
  }> = [];
  let plan: Array<{ id: string; label: string; status: string }> = [];
  let citations: Array<{
    documentId: string;
    title: string;
    similarity?: number;
    source?: string;
  }> = [];
  let finalText = "";
  let endedAt: string | undefined;
  let persisted = false;
  const toolFingerprints = new Set<string>(); // 工具去重：同一 miss 不刷屏

  /** 追加事件并 enforce TRACE_EVENTS_MAX，尽量保留首条 intent */
  const push = (
    kind: AgentTraceEventKind,
    summary: string,
    extra?: Partial<(typeof events)[number]>,
  ) => {
    events.push({
      ts: nowIso(),
      kind,
      summary,
      ...extra,
      detail: extra?.detail !== undefined ? truncateTraceText(extra.detail) : undefined,
    });
    while (events.length > TRACE_EVENTS_MAX) {
      // 尽量保留首条 intent，丢掉较旧的非 intent
      const dropIdx = events.findIndex((e, i) => i > 0 && e.kind !== "intent");
      if (dropIdx >= 0) events.splice(dropIdx, 1);
      else events.shift();
    }
  };

  push(
    "intent",
    `路由=${input.intent.route}；强制专科=[${input.intent.requiredSpecialists.join(", ") || "无"}]`,
    { name: "intent", detail: truncateTraceText(input.userText, 500) },
  );

  /** 组装前端下载 / data-agent-trace 用的完整结构 */
  const toDocument = () => ({
    threadId: input.threadId,
    startedAt,
    endedAt,
    userText: truncateTraceText(input.userText, 2000),
    intent: input.intent,
    plan,
    events: [...events],
    citations,
    finalText: finalText ? truncateTraceText(finalText, TRACE_FINAL_MAX) : undefined,
    meta: { langsmithProject: input.langsmithProject, persisted },
  });

  return {
    recordPlan(items: typeof plan) {
      // 待办快照变更时记一条 plan 事件
      plan = items.map((i) => ({ id: i.id, label: i.label, status: i.status }));
      push("plan", `待办${plan.length} 项：${plan.map((p) => p.label).join(" → ") || "(空)"}`, {
        name: "plan",
      });
    },
    recordSpecialist(agent: string, summary: string, detail?: string) {
      push("specialist", summary, { agent, name: agent, detail });
    },
    recordTool(inputTool: {
      name: string;
      summary: string;
      detail?: string;
      agent?: string;
    }) {
      const blob = `${inputTool.summary}\n${inputTool.detail ?? ""}`;
      // kb miss 合并成同一指纹，避免刷屏
      const fp =
        inputTool.name === "kb_search" && /NO_RELEVANT_HIT/i.test(blob)
          ? "kb_search:NO_RELEVANT_HIT"
          : `${inputTool.name}\0${inputTool.summary}\0${(inputTool.detail ?? "").slice(0, 160)}`;
      if (toolFingerprints.has(fp)) return;
      toolFingerprints.add(fp);
      push("tool", inputTool.summary, {
        name: inputTool.name,
        agent: inputTool.agent,
        detail: inputTool.detail,
      });
    },
    recordIntermediate(agent: string, text: string) {
      const clipped = truncateTraceText(text);
      if (!clipped) return;
      push("intermediate", `${agent} 中间输出${clipped.length} 字`, {
        agent,
        name: "intermediate",
        detail: clipped,
      });
    },
    recordError(summary: string, detail?: string) {
      push("error", summary, { name: "error", detail });
    },
    setCitations(cites: typeof citations) {
      citations = cites.map((c) => ({ ...c }));
      if (citations.length) {
        push(
          "citation",
          `引用${citations.length} 条：${citations.map((c) => c.documentId).join(", ")}`,
          { name: "citations" },
        );
      }
    },
    appendFinalText(delta: string) {
      finalText += delta;
    },
    setFinalText(text: string) {
      finalText = text;
    },
    finish() {
      // 流结束：补 endedAt，有终稿则记 final 事件
      endedAt = nowIso();
      if (finalText.trim()) {
        push("final", `终稿${Math.min(finalText.length, TRACE_FINAL_MAX)} 字（可截断）`, {
          name: "final",
          detail: truncateTraceText(finalText, 400),
        });
      }
      return toDocument();
    },
    toMarkdown() {
      const doc = toDocument();
      const lines = [
        `# Agent 执行轨迹`,
        ``,
        `- threadId:\`${doc.threadId}\``,
        `- route: **${doc.intent.route}**`,
        ``,
        `## 事件时间线`,
        ``,
      ];
      for (const e of doc.events) {
        lines.push(`###${e.ts} ·${e.kind}`, ``, e.summary, ``);
      }
      return lines.join("\n");
    },
    /** 可选落盘；默认关，写盘失败 fail-open 返回 null */
    persistIfEnabled() {
      if (process.env.AGENT_TRACE_PERSIST !== "true") return null;
      endedAt = endedAt ?? nowIso();
      try {
        const dir =
          process.env.AGENT_TRACE_DIR?.trim() || resolve(process.cwd(), ".data/agent-traces");
        mkdirSync(dir, { recursive: true });
        const stamp = (endedAt ?? nowIso()).replace(/[:.]/g, "-");
        const safeThread = sanitizeTracePathSegment(input.threadId);
        const base = resolve(dir, `${safeThread}-${stamp}`);
        persisted = true;
        const doc = toDocument();
        try {
          writeFileSync(`${base}.json`, `${JSON.stringify(doc, null, 2)}\n`);
          writeFileSync(`${base}.md`, toMarkdown());
        } catch (err) {
          persisted = false;
          throw err;
        }
        return base;
      } catch {
        persisted = false;
        return null;
      }
    },
  };
}
```


默认 **不落盘**；仅当 `AGENT_TRACE_PERSIST=true` 时写 JSON + Markdown 到 `.data/agent-traces/`（可用 `AGENT_TRACE_DIR` 覆盖目录）。


### 6.3 前端提取与下载


```typescript
import type { UIMessage } from "ai";

/** 从 message.parts 提取最新一条 data-agent-trace */
export function extractAgentTrace(message: UIMessage): {
  threadId: string;
  events: Array<{ kind: string; summary: string; detail?: string }>;
  intent: { route: string; requiredSpecialists: string[] };
  // …其余字段与文档一致
} | null {
  let latest: unknown = null;
  // 同一消息可能多次写入，保留最后一条完整 trace
  for (const part of message.parts) {
    if (!("type" in part) || typeof part.type !== "string") continue;
    if (part.type !== "data-agent-trace") continue;
    const data = "data" in part ? part.data : undefined;
    if (data && typeof data === "object" && Array.isArray((data as { events?: unknown }).events)) {
      latest = data;
    }
  }
  return latest as ReturnType<typeof extractAgentTrace>;
}

/** 触发浏览器下载 MD/JSON，无需额外后端接口 */
export function downloadBlob(filename: string, content: string, mime: string) {
  const blob = new Blob([content], { type: mime });
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = filename;
  document.body.appendChild(a);
  a.click();
  a.remove();
  setTimeout(() => URL.revokeObjectURL(url), 0);
}

// 面板：下载 Markdown / JSON（按钮绑定 toMarkdown(doc) 与 JSON.stringify(doc)）
```


待办侧对称：`extractTodos` 扫 `data-todo-update`，保留**最后一次**完整 todos 数组。

## 8. 如何验证


| 输入 / 条件                    | 期望                                  |
| -------------------------- | ----------------------------------- |
| Agent 多步「先知识库再报告」          | 待办列表出现；步骤从 pending→active→completed |
| 闲聊「你好」                     | 可有短路步骤；todos 可被空数组清掉残留              |
| `AGENT_TRACE_PERSIST` 未设   | 不写 `.data/agent-traces`             |
| `AGENT_TRACE_PERSIST=true` | 同目录出现 `.json` + `.md`               |
| 反复同一 kb miss               | 轨迹里 tool 不无限重复                      |
| 流结束后气泡                     | 「执行轨迹」面板可下载 MD/JSON                 |


## 9. 诚实边界

- 轨迹是**摘要级**观测，不是完整 token 回放；`detail` 截断到 `TRACE_DETAIL_MAX`。
- `TRACE_EVENTS_MAX=200` 是经验护栏，不是评测科学值。
- 前端轨迹仅在助手消息且**非 streaming** 时展示，避免流中途布局狂跳。
- 未做跨进程集中式 trace 存储；落盘是本机评测用。
- 无成功率 / P95 轨迹长度 KPI。

## 10. 收束

1. 长任务需要进度，是因为「慢」和「挂」在 UI 上同形。
2. SSE data part 把待办、步骤、轨迹绑在同一条助手消息上。
3. Collector 用上限 + 工具指纹，避免轨迹变成第二故障源。
4. 落盘默认关；演示靠下载，评测靠显式 env。
5. `start` 必须先于自定义 data-*，否则前端消息拆分。
