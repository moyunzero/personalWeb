### **第 2 节：面向智能体的大语言模型基础**


智能体运行在大语言模型之上。你构建的每一个智能体、它发起的每一次工具调用、它采取的每一个推理步骤，都是由大语言模型生成词元来驱动的。如果你不理解大语言模型如何工作、会在哪里失败、以及可以调节哪些旋钮，你就会构建出不可靠的智能体，而且当它们出问题时，你也无法调试。


**我们将覆盖的内容**

1. Transformer 架构：它做什么，以及如何解释它
2. 词元与上下文窗口：智能体的工作记忆限制
3. 推理、温度与确定性：为什么智能体需要可预测的输出
4. 直接驱动智能体架构决策的大语言模型局限性
5. 模型选择：为你的智能体任务选择合适的模型

**这些内容在智能体系统中的体现位置**


| 智能体组件          | 它依赖的大语言模型基础           |
| -------------- | --------------------- |
| 核心推理循环（第 3 节）  | Transformer 推理、下一词元预测 |

### Transformer 架构


**Transformer 做什么**


Transformer 接收一个词元序列作为输入，并预测下一个词元。它反复这样做，一次生成一个词元，直到生成完整回复。这就是 ChatGPT、Claude、Gemini 以及当今所有驱动智能体的大语言模型背后的全部机制。


**你需要掌握的三个概念**


**注意力**


这种机制让模型权衡输入中哪些词元对预测下一个词元最相关。当模型看到“客户的订单在周二发货，并在”时，它会重点关注“发货”“周二”和“并在”，以预测下一个词。


**层**


Transformer 堆叠多个处理层（GPT-4 约有 120 层）。每一层都会细化模型的理解。早期层捕捉基本模式（语法、句法）。后期层捕捉复杂推理（意图、逻辑、上下文）。


**参数**


模型中存储的学习到的权重。GPT-4 估计有 1.8 万亿参数。参数越多通常意味着能力越强，但运行也更慢、更昂贵。


```plain text
简化的 Transformer 处理流程：

输入："Where is my order?"

步骤 1：词元化     → ["Where", " is", " my", " order", "?"]
步骤 2：嵌入        → 每个词元变成一个数值向量
步骤 3：注意力      → 模型判断 "order" 是关键概念
        （x120 层）   每一层细化理解
步骤 4：预测        → 下一个词元概率："Your" (0.35),
                        "I" (0.28), "The" (0.15), ...
步骤 5：选择        → 选择 "Your" → 加入序列 → 从步骤 3 重复
```


**该说什么 vs 该跳过什么**


| 说这个                                     | 跳过这个                  |
| --------------------------------------- | --------------------- |
| “注意力让模型权衡输入的哪些部分对当前预测最重要”               | Q/K/V 矩阵乘法、softmax 公式 |
| “模型通过多层处理输入，每一层都细化理解”                   | 具体层数、残差连接、层归一化        |
| “参数越多意味着能力越强，但更慢、更昂贵”                   | 精确参数数量、训练方法、梯度下降      |
| “模型一次生成一个词元，每个词元都以之前所有词元为条件”            | 束搜索内部机制、采样算法、logit 处理 |
| “Transformer 在大规模文本数据集上预训练，并可以针对特定任务微调” | 预训练数据组成、RLHF 细节、损失函数  |

> 
>
> **提示：** 如果被问到“大语言模型如何工作？”，用 60 秒讲完这个解释，并立即连接到它对智能体为什么重要：“因为模型按顺序生成词元，并且只能看到自己的上下文窗口，所以我们需要仔细管理放入该窗口的信息。这就是为什么上下文工程和记忆系统对智能体至关重要。”

### 词元、上下文窗口，以及它们为什么对智能体重要


**词元化**


大语言模型不处理单词，而是处理词元。词元是子词单元，在英语中通常为 3-4 个字符。大致来说：1 个单词 ≈ 1.3 个词元。模型的词表是一组固定词元（GPT-4 使用约 100,000 个唯一词元），每个输入和输出都会被拆分成来自该词表的序列。


```plain text
词元化示例：

"Hello world"           → ["Hello", " world"]                    = 2 个词元
"customer support"      → ["customer", " support"]               = 2 个词元
"authentication"        → ["authentication"]                     = 1 个词元
"I need a refund"       → ["I", " need", " a", " ref", "und"]   = 5 个词元
"राम"                   → ["र", "ा", "म"]                        = 3 个词元

经验法则（英语）：1 个单词 ≈ 1.3 个词元，1 页文本 ≈ 500 个词元
非英语语言通常每个单词使用 2-4 倍更多词元。
```


**上下文窗口：智能体的工作记忆**


上下文窗口是模型一次能看到的最大词元数。智能体需要知道的一切——系统提示、对话历史、工具结果、检索到的文档——都必须放进这个窗口。


| 模型              | 上下文窗口   | 大约文本页数    |
| --------------- | ------- | --------- |
| GPT-4o          | 128K 词元 | 约 256 页   |
| GPT-4o-mini     | 128K 词元 | 约 256 页   |
| Claude Sonnet   | 200K 词元 | 约 400 页   |
| Gemini 1.5 Pro  | 1M 词元   | 约 2,000 页 |
| Llama 3.1 (70B) | 128K 词元 | 约 256 页   |


大上下文窗口看起来很大方，但智能体消耗它们非常快。


**为什么这对智能体重要：一个完整示例**


```plain text
客户支持智能体的上下文窗口预算（128K 词元）：

系统提示：                  2,000 词元  （固定）
工具定义（4 个工具）：      1,200 词元  （固定）
检索到的知识块：            3,000 词元  （每次查询，3 块 x 1,000）
每轮对话：
  - 用户消息：                150 词元
  - 智能体推理：              200 词元
  - 工具调用 + 结果：         800 词元
  - 智能体回复：              250 词元
  - 每轮总计：              1,400 词元

固定开销：                  3,200 词元
剩余用于对话：              124,800 词元
溢出前轮数：                124,800 / 1,400 ≈ 89 轮

但如果 RAG 检索 10 块而不是 3 块：  每次查询 +7,000 词元
如果工具结果是冗长的 JSON：          每次调用 +2,000 词元
现在每轮约 4,600 词元：              124,800 / 4,600 ≈ 27 轮
```


89 轮听起来很舒适。而在现实检索和工具冗长程度下，27 轮才是真正的约束。这就是为什么需要上下文工程（第 5 节）。

> 
>
> **提示：** 在设计智能体时，一定要提到上下文窗口预算。这表明你理解一个大多数人会跳过的实际约束。可以说：“我会为系统提示分配大约 2K 词元，为检索分配 3-5K，并用滑动窗口回退方案为对话历史预算剩余窗口。”
>
>

### 推理、温度与确定性


**大语言模型如何生成回复**


推理是生成输出词元的过程。模型一次生成一个词元。每一步，它都会计算所有可能下一词元的概率分布，选择一个，追加到序列中，然后重复。一个 200 词元的回复需要 200 个顺序预测步骤。


这就是大语言模型回复需要时间的原因。不同于立即返回的数据库查询，模型必须按顺序计算每个词元。更长的回复按比例花费更长时间。


**温度：控制随机性**


温度控制模型如何从概率分布中选择。它是智能体行为最重要的单个参数。


| 温度      | 行为   | 词元选择            | 用例               |
| ------- | ---- | --------------- | ---------------- |
| 0       | 确定性  | 总是选择概率最高的词元     | 智能体工具调用、分类、结构化输出 |
| 0.1-0.3 | 近确定性 | 轻微变化，强烈偏向最高概率词元 | 生产智能体、客户支持、数据抽取  |
| 0.5-0.7 | 平衡   | 中等变化，有创意但连贯     | 内容起草、有护栏的头脑风暴    |
| 0.8-1.0 | 创意   | 高变化，令人惊讶的输出     | 创意写作、想法生成        |
| >1.0    | 混乱   | 近乎随机选择          | 生产中几乎从不有用        |


**为什么智能体需要低温度**


一个客户支持智能体如果对同一问题每次给出不同答案，它就是坏的。如果客户问“你们的退货政策是什么？”，并在三次会话中得到三个不同答案，那么无论这三个答案是否恰好都正确，系统都是不可靠的。一致性是产品需求。


```python
from openai import OpenAI

client = OpenAI()

def classify_customer_intent(message: str) -> str:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        temperature=0,
        messages=[
            {
                "role": "system",
                "content": "Classify the customer message into exactly one category: "
                           "order_status, refund_request, product_question, complaint, other"
            },
            {"role": "user", "content": message}
        ]
    )
    return response.choices[0].message.content

def draft_customer_response(message: str, context: str) -> str:
    response = client.chat.completions.create(
        model="gpt-4o",
        temperature=0.2,
        messages=[
            {
                "role": "system",
                "content": "You are a customer support agent. Use the provided context "
                           "to draft a helpful, empathetic response."
            },
            {"role": "user", "content": f"Context:{context}\n\nCustomer:{message}"}
        ]
    )
    return response.choices[0].message.content
```


注意这个模式：分类用 temperature=0（必须是确定性的），回复生成用 temperature=0.2（轻微变化可以接受，但回复仍应一致且专业）。


**Top-p（核采样）**


温度的一种替代方案。Top-p 不是缩放概率，而是截断分布：只考虑累积概率之和达到 p 的词元。Top-p=0.1 意味着只有覆盖概率质量前 10% 的词元是候选。


在实践中，对于智能体：设置 temperature=0 或 temperature=0.2，并让 top-p 保持默认值。不要同时调这两个参数。

> 
>
> **提示：** 如果问“你如何确保智能体行为一致？”，温度是第一个要提到的，其次是结构化输出和确定性工具模式。可以说：“我对所有分类和工具调用步骤设置 temperature 为 0，对回复生成设置 0.1-0.2。结合结构化输出约束，这让我们在相同输入上获得近乎确定性的行为。”
>
>

### 驱动智能体架构的大语言模型局限性


**每一个主要的智能体架构决策，都是为了补偿某种大语言模型局限性**


大语言模型能力非凡，但它们有根本性局限，无法通过使用更大的模型或写更好的提示来修复。这些局限是结构性的。理解它们是理解智能体架构为什么长成这样的关键。


**局限 1：幻觉**


模型生成自信、流畅且完全错误的信息。它并不“知道”自己错了。幻觉不是一个会在下一版本修复的缺陷。它是下一词元预测工作方式的固有属性：模型优化的是文本的合理性，而不是事实准确性。


示例：一个支持智能体被问到“ProMax 500 的保修期是什么？”时，幻觉出“2 年制造商保修”，而实际保修期是 90 天。回复听起来很权威。客户相信了。公司现在有了责任风险。


**局限 2：上下文窗口限制**


模型看不到上下文窗口之外的内容。没有“向上滚动”机制。如果信息在 50 轮对话的第 1 轮中，但已经被挤出窗口，那它就消失了。模型不记得它。它无法引用它。


示例：客户在 20 条消息中解释了一个复杂问题。到第 25 条消息时，最早的消息已经被逐出上下文。智能体要求客户重新解释他们已经详细描述过的内容。


**局限 3：没有实时知识**


模型的训练数据有截止日期。它不知道训练之后发生的事件、产品变化、价格更新或政策修订。它无法访问互联网、检查数据库或查找当前信息，除非你给它工具来这样做。


示例：客户问“ProMax 500 有库存吗？”模型无法回答这个。答案每小时都在变。没有检查库存的工具，智能体要么拒绝回答，要么幻觉。


**局限 4：延迟与成本**


每次大语言模型调用需要 0.5-5 秒并且花钱。一个智能体如果为处理一次客户查询进行 8 次顺序大语言模型调用，就需要 10 秒以上，并且成本是单次调用的 8 倍。延迟会随顺序推理步骤累积，成本会随词元量线性增长。


示例：一个智能体在回复前推理 5 步、检索 3 个文档、调用 2 个工具，需要 12 秒。客户已经切换到拨打 phone support 了。


**从局限性视角看本课程路线图**


| 大语言模型局限性 | 会出现什么问题    | 智能体架构解决方案        | 课程章节   |
| -------- | ---------- | ---------------- | ------ |
| 幻觉       | 自信的错误答案    | 将回复基于检索到的事实（RAG） | 第 6 节  |
| 幻觉       | 编造工具结果     | 输出验证、护栏          | 第 9 节  |
| 上下文限制    | 忘记较早对话     | 记忆系统、摘要          | 第 5 节  |
| 上下文限制    | 无法使用大型知识库  | 分块、检索、词元预算       | 第 6 节  |
| 无实时知识    | 无法回答当前状态问题 | 通过工具调用获取实时数据     | 第 4 节  |
| 无实时知识    | 政策信息过期     | 使用更新文档的 RAG      | 第 6 节  |
| 延迟       | 响应慢、用户体验差  | 并行工具调用、流式输出、缓存   | 第 11 节 |
| 成本       | 规模化时昂贵     | 模型路由、语义缓存        | 第 11 节 |
| 非确定性     | 回复不一致      | 低温度、结构化输出        | 第 4 节  |


这张表就是整个课程的架构。每一节的存在，都是因为这张列表中的某个局限性。

> **提示：** 当被问到“使用大语言模型构建的挑战是什么？”时，逐一讲这四个局限性，并立即把每一个连接到架构解决方案。这能证明你以工程权衡的方式思考，而不只是 API 调用。

### 为你的智能体选择合适的模型


**模型选择是工程决策，不是品牌偏好**


为你的智能体选择模型，不是挑“最好的大语言模型”。它是在五个维度上将模型能力与任务需求匹配：推理质量、上下文窗口大小、延迟、每词元成本和可用性。


**模型对比（代表性，2025 年中）**


| 维度            | GPT-4o   | GPT-4o-mini | Claude Sonnet | Gemini 1.5 Pro | Llama 3.1 70B |
| ------------- | -------- | ----------- | ------------- | -------------- | ------------- |
| 推理质量          | 非常强      | 适合简单任务      | 非常强           | 强              | 强             |
| 上下文窗口         | 128K     | 128K        | 200K          | 1M             | 128K          |
| 延迟（首词元时间）     | 约 300ms  | 约 150ms     | 约 350ms       | 约 400ms        | 取决于基础设施       |
| 输入成本（每 1M 词元） | 约 $2.50  | 约 $0.15     | 约 $3.00       | 约 $1.25        | 自托管成本         |
| 输出成本（每 1M 词元） | 约 $10.00 | 约 $0.60     | 约 $15.00      | 约 $5.00        | 自托管成本         |
| 最适合           | 复杂推理、规划  | 分类、抽取、路由    | 长上下文任务、细致分析   | 非常大的上下文需求      | 本地部署、数据隐私     |


注意：定价和能力经常变化。这些是代表性数值，用于说明成本-能力权衡。生产决策前始终检查当前定价。


**模型路由模式**


大多数生产智能体不使用单一模型。它们根据复杂度将不同任务路由到不同模型。


```python
from openai import OpenAI
import anthropic

openai_client = OpenAI()
anthropic_client = anthropic.Anthropic()

def route_to_model(intent: str, message: str, context: str) -> str:
    if intent in ("order_status", "product_question", "other"):
        response = openai_client.chat.completions.create(
            model="gpt-4o-mini",
            temperature=0,
            messages=[
                {"role": "system", "content": "Answer the customer query using the provided context."},
                {"role": "user", "content": f"Context:{context}\n\nCustomer:{message}"}
            ]
        )
        return response.choices[0].message.content

    elif intent in ("refund_request", "complaint"):
        response = anthropic_client.messages.create(
            model="claude-sonnet-4-20250514",
            max_tokens=1024,
            temperature=0.2,
            system="You are a senior support agent handling sensitive cases. "
                   "Be empathetic, follow policy precisely, and explain decisions clearly.",
            messages=[
                {"role": "user", "content": f"Context:{context}\n\nCustomer:{message}"}
            ]
        )
        return response.content[0].text
```


**为什么模型路由有效**


在客户支持智能体中，大约 60% 的查询是简单查找（订单状态、产品信息、FAQ）。这些不需要强大的推理模型。将它们路由到 GPT-4o-mini，按每 1M 输入词元 $0.15 计费，而不是 GPT-4o 的每 1M 输入词元 $2.50，在规模化时能节省大量成本。


```plain text
每天 10,000 次交互的成本对比：

不使用路由（全部 GPT-4o）：
  10,000 x 3,000 输入词元 x ($2.50 / 1M) = $75/天 输入
  10,000 x 500 输出词元 x ($10.00 / 1M)  = $50/天 输出
  总计：$125/天 = $3,750/月

使用路由（60% GPT-4o-mini，40% GPT-4o）：
  6,000 x 3,000 x ($0.15 / 1M) = $2.70/天   （简单查询）
  4,000 x 3,000 x ($2.50 / 1M) = $30.00/天   （复杂查询）
  6,000 x 500 x ($0.60 / 1M)   = $1.80/天    （简单输出）
  4,000 x 500 x ($10.00 / 1M)  = $20.00/天    （复杂输出）
  总计：$54.50/天 = $1,635/月

节省：$2,115/月（降低 56%）
```


复杂查询仍然使用强大模型。简单查询使用快速、便宜的模型，并且它们完全能处理好。质量保持不变。成本下降超过一半。

### 本节速查表


**覆盖的概念**


| 概念          | 一句话总结                                 |
| ----------- | ------------------------------------- |
| Transformer | 输入词元，输出下一词元预测，通过多层参数上的注意力实现           |
| 注意力         | 让模型权衡哪些输入词元对当前预测最重要的机制                |
| 词元          | 子词单元（每个英语单词约 1.3 个词元）。输入、输出、成本和上下文的单位 |
| 上下文窗口       | 模型一次能看到的最大词元数。智能体的硬性工作记忆限制            |
| 温度          | 控制输出随机性。0 = 确定性。智能体使用 0-0.2 以保证可靠性    |
| 幻觉          | 模型生成自信但错误的文本。通过 RAG、工具接地、护栏缓解         |
| 模型路由        | 简单任务用便宜模型，复杂任务用昂贵模型。节省 40-60% 成本      |


**常见错误**


| 错误                               | 为什么错                           | 更强的回答                                                  |
| -------------------------------- | ------------------------------ | ------------------------------------------------------ |
| “我会所有事情都用 GPT-4，因为它是最好的模型”       | 忽视成本和延迟权衡。没有生产思维。              | “我会把简单任务路由到更小的模型，并把昂贵模型保留给复杂推理。”                       |
| “上下文窗口是 128K 词元，所以我们可以把所有东西都放进去” | 忽视智能体组件（系统提示、工具、检索、历史）会快速消耗词元  | “我会为每个类别设置词元预算：2K 系统提示、5K 检索，以及用于历史的滑动窗口。”             |
| “幻觉是会在新模型中修复的缺陷”                 | 幻觉是下一词元预测的结构性问题，不是软件缺陷         | “幻觉是大语言模型工作方式的固有属性。我通过 RAG 接地、工具验证和输出护栏来缓解它。”          |
| “我会把温度设为 1，以获得更有创意的回复”           | 智能体回复必须一致可靠，而不是有创意             | “我对分类和工具调用使用温度 0，对回复生成使用 0.2。”                         |
| “Transformer 像人类一样理解语言”          | Transformer 以统计方式预测词元。它们不理解意义。 | “Transformer 是在文本上训练的统计模式匹配器。它们产生非常有用的输出，但并不以人类的方式理解。” |
