## 这实验能帮你什么


读完并跟着做，你应该能清楚回答：

1. 注意力热力图的**行 / 列**分别是什么？颜色亮代表什么？
2. **因果三角**和 **Attention Sink** 在图上长什么样？代码怎么用数值验收？
3. `attention_cli.py`（看图）和 `run_attention_experiment.py`（交卷）差在哪？
4. `evidence.json` 里 `regions` / `metrics` / `gates` 该怎么读？
5. 这些观察如何衔接到后文的 **KV Cache** 与上下文设计？

一句话结论：

> 每个新词用 **Query** 去匹配前面词的 **Key**，再按权重取 **Value**。
>
> 因为只能看过去 → 热力图呈因果三角；因为 softmax 权重必须加满 100% → 常把「剩余注意力」倒进第一个 token（Attention Sink）。
>
>
> **K/V 正是沿这条因果链被缓存与复用的**——所以改前缀会伤缓存。
>
>

## 1. 实验在证明什么


实验 2-2 不测「会不会调工具」，而测**模型内部注意力**是否呈现书中描述的可观测模式。


台账要求（`EXPERIMENT_LEDGER`）：真实热力图与矩阵须覆盖：

- 因果三角（causal triangle）
- Attention Sink
- 思考 / 输出区域
- 位置相关测量

### 1.1 用一句话理解 Q / K / V


以「北京 的 天气 怎么样」为例：当处理到「怎么样」时——


| 向量        | 角色         | 直觉              |
| --------- | ---------- | --------------- |
| **Query** | 当前词的「搜索请求」 | 「我在找谁？」         |
| **Key**   | 每个词的「标签」   | 「我是地名 / 气象 / …」 |
| **Value** | 每个词的「内容」   | 匹配成功后真正被抽走的信息   |


热力图约定：

- **行** = Query 位置（当前词）
- **列** = Key 位置（被关注的词）
- 格子越亮 ≈ 注意力权重越大（方向对）
- 正式脚本 `draw()` 用的是 **`log10(attention)`** 色标（colorbar 标为 `log10 attention`），不是线性比例；不要把色条当成 0→1 的线性刻度读

### 1.2 书中要你亲眼看到的模式

1. **Attention Sink（注意力储存池）**

    第一个 token 常吸收异常高的注意力（末层常见约 75–85%）。不是模型坏了：softmax 要求一行权重和为 1，模型无法表达「谁都不看」，剩余权重需要稳定容器，开头位置往往成为「回收站」。

2. **因果三角**

    从左到右生成：位置 `i` 只能看 `j ≤ i`。未来位置被 mask → 热力图右上角接近全黑。

3. **思考区 / 回答区**

    生成序列中出现 `<think>...</think>` 与最终答案；正式实验用下标把两区切开。

4. **位置相关测量（观测项，非硬性门）**

    书中讨论 Lost in the Middle；本实验用 `position_mass_per_token` **观测**分布。注意它的定义比口头经验更窄（见 §5.4）：只统计**后半段 Query 行**对 Key 前/中/后三分位的平均质量，**不是**单独的完成门，也不是对书中经验律的严格复现检验。协议 / `observational_note` 写明：幅度是测量结果，不是必须刷漂亮的完成条件。


另：书中「思考三角 / 输出三角」是直观描述；代码**没有**单独的「两个三角长得像」gate，只验 `thinking_region_present` / `final_answer_region_present`（区域非空）。

## 4. 两条路径：看图 vs 交卷


### 4.1 体验：`attention_cli.py`


```bash
cd chapter2/attention_visualization
source ../../.venv/bin/activate

python attention_cli.py \
  --prompt "北京 的 天气 怎么样" \
  --output "my_beijing_attention.png" \
  --compare-layers 0 13 -1
```

- `-compare-layers 0 13 -1`：第 0 层、中间层、最后一层并排
- 终端打印各层 **attention sink mean**
- 可选 `-max-new-tokens N` 先生成再可视化（正式实验才强制生成思考链）

### 4.2 正式：`run_attention_experiment.py`


流水线概要：

1. 读协议 → **本文件内**加载 `Qwen/Qwen3-0.6B`（`attn_implementation="eager"`，才能拿到 attention）
2. **simple**：对钉死的北京句做前向，抓协议里的 `layers`（学习协议常用 `[0, 13, -1]`）
3. **generated**：硬编码 system「你是一个会展示简短思考过程的助手。」+ 协议里的 `reasoning_prompt`；`apply_chat_template(..., enable_thinking=True)`；`generate(..., do_sample=False)` 贪心解码；再抓同一组层
4. `capture`：对各层 attention **在 head 维求平均**，得到二维矩阵
5. `region_indices` 用 `<think>` / `</think>` 切思考区与回答区
6. `matrix_metrics` 算 sink / 上三角 / `position_mass_per_token`
7. 写 PNG（log10 色标）、NPZ、`evidence.json`、`manifest.json`，并把 manifest **复制覆盖**到 `validation/latest.json`

口诀：

> **CLI 看图建立直觉；****`run_attention_experiment`** **交可审计证据。**

## 5. 关键代码：数字从哪来


### 5.1 Sink = 第 0 列的平均


```python
"attention_sink_mean": float(matrix[:, 0].mean())
```


矩阵形状为 `[Query, Key]` 时，`[:, 0]` 就是「所有当前词对**第一个 token** 的注意力」的平均。


正式路径里该矩阵已是 **所有 head 的平均**（`attentions[layer][0].mean(dim=0)`），不是某一个 head。


### 5.2 因果验收查「上三角」


```python
upper = matrix[np.triu_indices(length, k=1)]
# gate: causal_upper_triangle_max <= 1e-7
```

- 合法区域：下三角 + 对角线（`j ≤ i`）
- 必须接近 0：严格上三角（`j > i`，未来）
所以查上三角 = 查「有没有偷看未来」，不是查下三角有没有信号。

### 5.3 思考 / 回答区域


`region_indices` 只在 **`context_length`** **之后**的生成段里找：

- 第一个含 `<think>` 的下标 → 思考起点
- 其后第一个含 `</think>` 的下标 → 思考终点（含该 token）
- 再往后到序列末尾 → `answer`

若找不到 `</think>`，思考区会一直延伸到末尾，且 `answer` 为空 → `final_answer_region_present` 会失败。


gate 只要求两区 **非空**，不检验「三角图案像不像书上的示意图」。


### 5.4 `position_mass_per_token` 到底在算什么


```python
response_rows = np.arange(max(0, length // 2), length)  # 只取后半段 Query
# 对 Key 的 beginning / middle / end 三分位分别求平均质量
```


解读要点：

- 分子来自「后半段行 × 某一三分位列」的注意力质量和，再除以格子数
- 因此它回答的是：**序列后半段在看前段 / 中段 / 后段 Key 时，平均每格多重**
- 与口语「开头和结尾更受关注」相关，但**不是同一句话的严格实现**；幅度仅作观测

### 5.5 正式热力图色标


`draw()` 对矩阵做 `log10(max(attn, 1e-7))`，`vmin=-7, vmax=0`，cmap=`magma`。


标题里的 `sink=xx%` 仍用**线性**的 `matrix[:, 0].mean()`，与色标尺度无关。

## 9. 常见问题


**Q:** **`DTensor`** **ImportError？**


A: torch 过旧、transformers 过新。用 `uv sync --locked --extra ch2` 对齐。


**Q:** **`attention_experiment_protocol.json`** **找不到？**


A: 目录 `.gitignore` 忽略了 `*.json`。按上文补一份可跑协议。


**Q: 中文热力图方块字 / bold 字体 WARNING？**


A: 多为字体回退；一般不影响矩阵与 gates。需要时可配置 CJK 字体（见 `visualization.py`）。


**Q: CLI sink 和正式 simple sink 数字不完全一样？**


A: 是否套 chat template、序列长度不同；正式路径固定平均所有 head。看**趋势**（浅→深 sink 升高）即可。


**Q: 必须复现作者图里每一个色块吗？**


A: 否。完成门是结构与区域存在性、因果上三角、产物完整性；sink / 位置幅度是观测。正式 PNG 还是 log10 色标，色块观感会和线性想象有偏差。


**Q: 和前端 trajectory 的关系？**


A: `agent.py` / `main.py` + React 前端是另一条交互可视化路径；正文实验 2-2 的 canonical 验收以 `run_attention_experiment.py` 为准（不调用 `agent.py`）。


**Q: 为什么我一跑正式实验，****`validation/latest.json`** **就变了？**


A: 脚本故意把本次 manifest 复制过去，方便本机指向「最新一次」。需要作者原件时先备份，或从 git 恢复该文件。


**Q: 只改协议里的 prompt，system 怎么还是那句助手设定？**


A: generated 的 system 字符串硬编码在 `run_attention_experiment.py` 里，不在 protocol JSON。

## 10. 复习卡片

1. **行 = Query，列 = Key**；正式图用 **log10** 显示
2. **因果**：只能看过去 → 上三角应≈0
3. **Sink**：第 0 列吸收剩余注意力；深层更明显；矩阵已对 head 平均
4. **双入口**：CLI 看图（可走 `agent.py`）/ 正式脚本直连 Transformers 交卷
5. **eager attention** 才能导出矩阵
6. **regions** 用 `<think>` 切开思考与回答；无「双三角」独立 gate
7. **position_mass** = 后半段行对三分位列；幅度是观测，不是刷分门
