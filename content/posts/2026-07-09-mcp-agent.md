### MCP 是什么？


MCP 是 Anthropic 在 2024 年底提出的开放协议，目前主流 AI 编程工具（如 Cursor、Claude Code、Codex 等）已广泛支持。


**简单理解**：它是 **Agent 的 USB 接口**。


通过统一协议，Agent 可以“插上”各种外部工具和数据源，而无需为每个工具单独开发集成。


**能做什么**？

- 读取数据库 schema 和真实数据
- 访问接口文档
- 读取 GitHub Issue（含讨论背景）
- 打开浏览器查看页面实际效果
- 查询错误日志定位 Bug

没有 MCP 时，Agent 只能在本地仓库文件里“打转”；有了 MCP，它能触达真实工程环境。


### 为什么需要 MCP？


AI 常写出“看起来对、实际上不对”的代码，根源往往是**信息缺失**。


典型例子：

- 写查询接口时，AI 猜测数据库字段名，导致报错。
- 修 Bug 后说“应该没问题”，但你无法快速验证实际效果。

接上数据库 MCP → 直接读取真实表结构；接上浏览器 MCP → 自动打开页面验证改动。


**核心价值**：让 Agent 从“只能看代码”升级为“能看到真实环境”。


### 三个实战场景

1. **读数据库 Schema**

    直接查询表结构、字段、索引，写筛选功能时不再猜字段名。

2. **读接口文档**

    前后端分离项目中，AI 写前端请求时可直接参考后端 API 真实格式。

3. **访问 GitHub Issue**

    从 Issue #42 读取完整需求和讨论，直接基于真实背景出计划。


这些场景让 Agent 逐步接近你的真实工作流。


### 配置与使用习惯


配置不算复杂：

- Claude Code：`.mcp.json` 或 `claude mcp` 命令
- Cursor：设置界面或 `.cursor/mcp.json`

**重要提醒**：

- **不要一次性接太多**：每个 MCP Server 都会占用上下文预算（工具描述信息）。
- **按任务开关**：后端任务关浏览器 MCP，UI 任务再开启。
- **项目级记录**：在 [AGENTS.md](http://agents.md/) 中注明默认启用的 MCP。
- **定期清理**：删除长期不用的 Server。

### 权限风险


接的工具越多，权限风险越高。建议：

- 数据库用只读账号
- GitHub Token 权限最小化

### 小结


MCP 不是万能银弹，别一股脑全接。先从**最常缺信息**的那个开始（通常是数据库 MCP）。
