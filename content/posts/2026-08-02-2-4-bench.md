## 这实验能帮你什么


读完并跟着做，你应该能清楚回答：

1. 基线固定了哪三件事？三个消融轴各自只动哪一件？
2. 为什么主信号是 **τ-bench 客观通过率**，而不是「感觉更友好」？
3. `-all` 为什么不能随便改成「只跑 2 个任务」？
4. 书上「组织 −30%、工具错误 +45%」和 canonical 收据为何可以不一致，实验却仍算通过？
5. 仅有 `OPENROUTER_API_KEY` 时模型 id / 协议门禁怎么踩坑？

一句话结论：

> **提示工程像给聪明新员工写手册：** 语气影响体验，组织影响能不能按规则办事，工具描述影响会不会用工具。
>
> 本实验用控制变量在同一批航空客服任务上消融这三件，用客观 reward 打分。
>
>
> **验收看「跑完、同任务、真收据」；历史百分比不是完成门。**
>
>

## 2. 实验在证明什么


目录：`chapter2/prompt-engineering/`。


扩展 [τ-bench](https://arxiv.org/abs/2406.12045) 的 airline 场景：Agent 处理改签、退款等，用户由 LLM 模拟，环境按客观规则打分。


正式协议：`experiment_protocol.json`（`experiment_id: 2-4`）。


| 项                              | 冻结值                                      |
| ------------------------------ | ---------------------------------------- |
| 动作模型 / 用户模拟器                   | `kimi-k3` / `kimi-k3`                    |
| 运输（canonical）                  | Moonshot 官方 OpenAI 兼容端点                  |
| 任务                             | airline，`task_ids` 0–9，每任务 1 trial       |
| seed / temperature / max steps | `20260730` / `1` / `30`                  |
| 主指标                            | τ-bench **objective reward / pass rate** |
| 辅指标                            | Agent 步数、工具调用与错误、token、费用                |


台账（`EXPERIMENT_LEDGER`）：`validation/latest.json` 指向完成战役；**明确写明历史百分比未复现**，仍算 Passed。

## 5. Canonical 结果怎么读（v7）


指针：


```plain text
validation/latest.json
  run_dir: runs/exp2-4-kimi-k3-20260730-v7
  campaign_complete: true
  historical_percentages_reproduced: false
```


`comparison.json` 中六臂通过数（每臂 10 任务）：


| 臂             | 通过   | 成功率 |
| ------------- | ---- | --- |
| baseline      | 7/10 | 70% |
| tone_trump    | 6/10 | 60% |
| tone_casual   | 9/10 | 90% |
| wiki_random   | 8/10 | 80% |
| no_tool_desc  | 9/10 | 90% |
| all_ablations | 8/10 | 80% |


和书中历史说法对照：


| 书上说法                | v7 观察                                  |
| ------------------- | -------------------------------------- |
| 组织打乱 → 成功率降超过 ~30%  | **未出现**：wiki_random 反而 8/10 ≥ baseline |
| 去掉工具描述 → 工具错误升 ~45% | **未按该点估计复现**（本战役 no_tool_desc 通过率仍高）   |
| 语气对客观成功率影响相对有限      | 方向上语气臂仍在同量级波动，符合「有限」叙事的宽松读法            |


正确写法：

> 战役完成、收据齐全；**本固定 10 任务战役未复现历史点估计**。
>
> 把书上百分比当「某次历史观察」，把 v7 当「当前冻结复现结果」。
>
>

协议假设（`hypotheses`）仍可当讨论题：语气影响有限、组织打乱伤成功率、去描述伤工具使用——**用你手上的数字去证伪或限定条件**，不要为了迎合书而改收据。

## 6. 本机 live 记录


约束：仅使用 `OPENROUTER_API_KEY`（无 `OPENAI_API_KEY` / `MOONSHOT_API_KEY`）。


### 6.1 第一次失败：`-all` + 缩任务


```plain text
ValueError: Frozen protocol requires task IDs [0..9]; got [0, 1].
```


教训：想省钱缩任务，**不能**走 `--all`（除非另写本地 smoke 协议并用 `--protocol` 指向它；不要改仓库冻结文件）。


### 6.2 第二次：单臂 baseline 冒烟


命令要点：模型用 OpenRouter slug `moonshotai/kimi-k3`，显式 `--model-provider openrouter`，`--task-ids 0 1`，**不加** `--all`。


结果：两个 task 均 **402**——OpenRouter 额度不足（请求 `max_tokens` 至 4096，账户约只够 ~900 token 量级）。`reward: 0.0` 是**运输层 / 额度 blocked**，不是「模型答错」。


收据目录（失败证据，不当成功结论）：


```plain text
runs/exp2-4-or-smoke-20260811-v1/tool-calling-kimi-k3-baseline_0811151551.json
```


### 6.3 OpenRouter 实操清单


| 要点                             | 说明                                                                       |
| ------------------------------ | ------------------------------------------------------------------------ |
| `.env` 只留 `OPENROUTER_API_KEY` | 勿残留 `OPENAI_API_KEY` / `OPENAI_API_BASE`，避免抢路由                           |
| 模型 id                          | 冒烟用 `moonshotai/kimi-k3`；`--all` 冻结协议要裸名 `kimi-k3`（与 OpenRouter slug 冲突） |
| 余额                             | Kimi K3 不便宜；额度不够会 402，需充值或换更便宜模型做通路测试                                    |
| 与 canonical 关系                 | OpenRouter 是另一条运输层；完整验收仍以 Moonshot 冻结战役为准                                |

## 7. 常见问题


**Q: 必须自己跑满 6×10 才算学完？**


A: 学习上：读通协议 + 离线 `comparison.json` +（可选）通路冒烟即可。台账完成证据是作者侧 v7。


**Q:** **`wiki_random`** **高于 baseline，是不是实验坏了？**


A: 不一定。n=10、单 seed 噪声大；README 也警告小样本冒烟表不能当科学结论。记录观察，不要强行改写成「一定 −30%」。


**Q:** **`--resume-from`** **干什么？**


A: 战役中断后，把**已完成且合法**的任务收据导入新 `log-dir`，不重跑成功格；缺的/错的再跑。


**Q: 主信号为什么不是「用户满意度」？**


A: 本实验用环境客观 reward；语气对体验的影响书中有讨论，但门禁盯的是可审计的任务完成。

## 8. 复习卡片

1. **三轴**：语气 · 信息组织 · 工具描述
2. **基线** = 结构化手册 + 完整工具说明 + 专业中立
3. **主信号** = τ-bench 客观通过率
4. **`-all`** = 锁死冻结协议（10 任务 + 裸 `kimi-k3` 等）
5. **历史 % ≠ 完成门**；v7 未复现 30%/45% 仍 Passed
6. **OpenRouter**：用 `moonshotai/kimi-k3`；
