## 0. 零基础背景


### 为什么要测检索？


改一行融合代码，肉眼点三条聊天看不出有没有悄悄坏掉。需要**可重复的考卷**：固定问句、期望引用谁、禁止出现谁。


### Golden set（黄金集）

- **是什么**：一叠「标准答案题」——JSON 里写 query、期望 citation 来源、禁止来源等。
- **像什么**：高考题库 + 标准答案卡。
- **本项目**：`golden.json` 黄金集，例如问奥德赛 → 引用须像 `奥德赛计划书_….md`，且不得出现 `psychology-qa`。

### Regression（回归测试）

- **是什么**：自动跑的旧功能测试，防止「修 A 弄坏 B」。
- **像什么**：每次发车前按清单鸣笛、刹车、灯——不是新发明考试，是确认老功能还在。
- **本项目**：`yarn test:regression:phase-3`（hybrid、corpus、memory、graph、intent…）。

### Vitest / `it()`

- **是什么**：本仓库用的 JS/TS 测试框架；一个 `it("…")` 就是一条用例。
- **本项目**：说「27 个 it」= 当前套件里有 27 条用例，不是「通过率 27%」。

### Mock（模拟 / 打桩）

- **是什么**：测试时**不连真数据库/真 API**，用假函数返回假数据。
- **像什么**：消防演习用假火——练流程，不真烧楼。
- **本项目**：`yarn eval:phase-3` 的 smoke **是 mock**：假 embed、假向量命中。绿了 ≠ 线上召回率 100%。

### Smoke / Nightly

- **Smoke（冒烟）**：少而快，常跑，确认「主干没冒烟起火」。
- **Nightly（夜间全量）**：题更多、更慢，适合夜间或发布前。
- **本项目**：`eval:phase-3` vs `eval:phase-3:nightly`。

### Live / Full-flow / UAT

- **Live**：打真实 ES/Neo4j/浏览器，不是假数据。
- **Full-flow**：脚本把上传→检索→删除等链路跑通并截图。
- **UAT（User Acceptance Test）**：验收「对用户是否可接受」，常含 UI。
- **本项目**：Phase 3 / 3.1 验收脚本与 HTML 报告；和单元测试互补。

### CI 门禁

- **是什么**：合并代码前自动跑测试，红了不准合。
- **本项目**：评测命令可本地跑；是否绑死 PR 看当前 CI。文档里的「≥95%」常是**目标**，别当成已强制的线上 KPI。

### 诚实说法对照


| 说法                               | 靠谱吗           |
| -------------------------------- | ------------- |
| 「smoke 绿了所以召回率 100%」             | ❌ mock ≠ live |
| 「FULL-FLOW 某日记 regression 13/13」 | ✅ 有日期快照       |
| 「标准文档写目标 ≥95%」                   | ✅ 标明是目标       |

## 1. 开场矛盾


Phase 2 验收靠「手点 + smoke」：能演示，但 **改一行** **`hybridSearch`** **不知道坏了哪条契约**。v3 关账需要可重复命令，并且要诚实区分：

- **确定性 mock 评测**（CI 友好，不打真库）
- **live full-flow / UAT**（打真 ES/Neo4j/浏览器）
- **产品指标文档**（评测标准文档写目标，不等于已强制 CI）

把三者混成「我们召回率 95%」就是虚假内容。本篇只写代码与验收记录里**实际存在**的东西。


## 2. 本篇目标


讲清 `golden.json` 契约、`yarn eval:phase-3`（smoke）与 nightly、regression 套件分工。


**不负责**：模型对比脚本 KPI 宣传；Faithfulness 自动打分（标准文档有位、未落地门禁）。


---


## 3. 评测分层：为什么、优势、不做会怎样、原理


### 3.1 三层（命令以 `package.json` 为准）


| 层               | 命令                             | 实际测什么                                                     |
| --------------- | ------------------------------ | --------------------------------------------------------- |
| 回归              | `yarn test:regression:phase-3` | hybrid、corpus、memory、checkpointer、workspace、graph、intent… |
| Eval smoke      | `yarn eval:phase-3`            | **mock** hybrid + intent 断言（契约冒烟）                         |
| Eval nightly    | `yarn eval:phase-3:nightly`    | eval 套件全量                                                 |
| Full-flow / UAT | 验收脚本                           | live 存储 + 截图 / HTML 报告                                    |


验收记录（FULL-FLOW Wave H）：regression **13/13**；`yarn eval:phase-3` 记录为 **2/2**（当时 smoke 用例数）。**当前** smoke 套件含 **3** 条 `it`（golden 结构校验 + smoke hybrid + intent g23–g25）——以你本地跑出来的条数为准，勿把旧日志当永久常量。


### 3.2 golden 条目


```json
{
  "id": "g01",
  "query": "奥德赛计划书给了什么建议",
  "corpus": "user",
  "expectCitationSource": "奥德赛计划书_2026-06-30.md",
  "forbidSources": ["psychology-qa"]
}
```


意图类另有 `expectIntentPrimary` / `expectTool`（如 g23–g25）。


### 3.3 smoke 为何是 mock（重要）


```typescript
// smoke 注入 mock store / esSearch，不访问真 Astra/ES
const result = await hybridSearch(
  { query: item.query, workspaceId: "ws-golden-smoke", corpus: item.corpus, limit: 3 },
  {
    embed: async () => [0.1, 0.2],
    getStore: () => mockStore([hit]),
    esSearch: async () => [hit],
    rewriteQuery: async (q) => q,
  },
);
```


因此：**smoke 绿 ≠ 线上召回率达标**。它验证的是「hybrid 管道在给定 hits 时尊重 expect/forbid」与「意图解析契约」。


### 3.4 优势 / 不做会怎样


| 若取消…          | 后果                   |
| ------------- | -------------------- |
| forbidSources | psychology 混库可静默过关   |
| mock smoke    | CI 依赖外网配额，不稳定        |
| 与 live UAT 混谈 | 对外数字失真               |
| intent golden | graph_relation 漂移无人知 |

## 4. 方案取舍


| 方案                             | 采用理由                             |
| ------------------------------ | -------------------------------- |
| RAGAS 全自动                      | smoke 显式禁止 RAGAS/EVAL-01 命名污染；未接 |
| 仅人工点点                          | 无法回归                             |
| **mock smoke + live UAT + 回归** | 采用                               |

## 6. 关键实现（smoke 意图段）


```typescript
it("intent golden g23–g25: resolveIntentPlan primary + retrieverTools (D-09)", async () => {
  for (const item of intentItems) {
    const probeKb = vi.fn().mockResolvedValue({
      probed: true,
      topSimilarity: item.id === "g25" ? 0.9 : 0.2,
      title: item.id === "g25" ? "奥德赛计划书" : undefined,
    });
    const { plan } = await resolveIntentPlan(item.query, { probeKb });
    expect(plan.primary).toBe(item.expectIntentPrimary);
    if (item.expectTool) expect(plan.retrieverTools).toContain(item.expectTool);
    else expect(plan.retrieverTools).toEqual([]);
  }
});
```

## 9. 诚实边界

- **smoke 不访问生产向量库。**
- EVALUATION-STANDARD 中 Citation Hit ≥95% 等是**设计目标**；关账证据是 regression + UAT，不是持续 SLI。
- **未绑 PR 必绿 CI**（以仓库当前配置为准）。
- golden 文档名需与 fixture/语料约定一致；live 评测另需 seed 数据。

---


## 10. 收束

1. **回归保逻辑，smoke 保契约，UAT 保真链路。**
2. **禁止把 mock 通过率说成线上召回率。**
3. `forbidSources` 是混库问题的安全网。
