## 0. 零基础背景


**什么是 BFF / 反向代理？**


浏览器只跟「官网同域」的 Next.js（`:3000`）说话。Next 在服务端再去请求真正的 agent-service（`:3002`）。这层叫 **BFF（Backend for Frontend）**：专门为前端定制的后端门面。它也像一个**反向代理**：对外一个入口，对内转发。


**为什么令牌不能放进前端？**


若 `AGENT_INTERNAL_TOKEN` 写进 `NEXT_PUBLIC_*`，任何人打开 DevTools 就能复制，等于没锁。令牌必须只存在**服务器环境变量**，由 BFF 注入 `Authorization: Bearer …`。


**CORS 为什么也该留在服务端路径？**


若浏览器直连 `:3002`，就要在 agent 上配 CORS、暴露公网端口、处理预检。BFF 同域请求没有这堆浏览器跨域问题；agent 可以只听私网或本机。


第 2 篇写过流式消毒与代理踩坑；本篇把**产品双模**与 **BFF 安全边界**单独钉死。


**504 vs 502（白话）**：BFF 连上游时，**超时 / 用户取消**常映射成 **504**；**根本连不上**（地址错、进程没起、代理拐走 localhost）常是 **502**。本地排障先看 agent `/health`，再查 `NO_PROXY`。


**timingSafeEqual**：比较令牌时用常量时间比较，避免「猜对前缀更快返回」的计时侧信道；长度不同则直接判失败。

## 1. 开场矛盾


同一站点两个入口，工程上却常被合成「一个大 chat API」：

1. **Chat** 要稳：知识库引用、短问答。
2. **Agent** 要重：多专科、轨迹、可能更长超时。
3. **密钥**：agent 需要内部令牌；浏览器直连就会把秘密送到客户端。
4. **本机代理**：Clash 开着时，BFF→`localhost:3002` 若被误代理 → 整页 NETWORK / 502（第 2 篇已见）。

矛盾：**产品要两个模式，安全上却只能有一个「浏览器可见的 API 面」。**


## 2. 本篇目标


讲清 Chat vs Agent 产品分流、生产路径浏览器**不**直连 `:3002`、Next `/api/agent/chat` 注入 `AGENT_INTERNAL_TOKEN`、`EnvHttpProxyAgent` + `NO_PROXY`、以及 abort / 上游超时转发。


不展开流式 TransformStream 细节（第 2 篇）、不展开 checkpointer（第 11 篇）。


## 3. 双模与 BFF


### 3.1 总览


| 层/部件                | 做什么                                      | 代价                           | 代码入口          |
| ------------------- | ---------------------------------------- | ---------------------------- | ------------- |
| `page.tsx` mode     | Chat→`/api/chat`；Agent→`/api/agent/chat` | 两套 transport                 | §6.1          |
| BFF `POST`          | 读 body、注 Bearer、fetch 上游、泵流              | body 上限 1MB；超时 120s          | §6.2          |
| `AgentController`   | 生产强制校验内部令牌                               | 生产未配/不匹配 → 401；非生产仅在已配置令牌时校验 | §6.3          |
| `EnvHttpProxyAgent` | 出站代理尊重 `NO_PROXY`                        | 依赖 undici                    | §6.4          |
| abort 合并            | 客户端取消 + 上游超时                             | 504 vs 502 语义                | abort-signals |


### 3.2 为什么产品拆双模


|       | Chat                | Agent                             |
| ----- | ------------------- | --------------------------------- |
| 适合    | 短问答、KB 引用           | 多步调研、报告                           |
| API   | `/api/chat`（Next 内） | `/api/agent/chat` → agent-service |
| 过程 UI | 较少                  | 待办 / 步骤 / 轨迹                      |


合成一个后端会导致：闲聊误进整图、超时策略打架、错误文案无法分类（Agent 有专用 `AgentErrorCard`）。


### 3.3 为什么 BFF 而不是浏览器直连

- **令牌**：只在 Next 进程读 `AGENT_INTERNAL_TOKEN`。
- **网络面**：公网只暴露 Web；`:3002` 可留在私网 / 本机。
- **Abort**：用户点停止 → `req.signal` abort → BFF 取消上游 fetch；agent 侧 `attachResponseAbortSignal` 再取消 LangGraph。
- **错误整形**：502「不可达」/ 504「取消或超时」用固定中文，不回传上游堆栈。

### 3.4 优势


| 对比对象                                    | 本方案优势                         |
| --------------------------------------- | ----------------------------- |
| `NEXT_PUBLIC_AGENT_SERVICE_URL` + 浏览器直连 | 密钥与 CORS 不泄漏到客户端              |
| 无令牌、agent 公网裸奔                          | 生产 fail-closed（无 token → 401） |
| 全局 `ProxyAgent(url)` 无视 `NO_PROXY`      | 环回直连本机 agent，外网仍可走代理          |
| Chat/Agent 共用一个 timeout                 | Agent 单独 120s 上游超时更匹配长任务      |


### 3.5 不做会怎么样


| 若取消…                         | 会发生什么                 |
| ---------------------------- | --------------------- |
| 取消 BFF、浏览器直连 :3002           | 令牌进前端；CORS / 公网暴露     |
| 生产不强制 `AGENT_INTERNAL_TOKEN` | 任意人可打 agent 烧模型与工具    |
| 取消 abort 转发                  | 用户停了，图仍在跑，浪费配额        |
| 取消 body 大小上限                 | 超大 messages 拖垮 BFF 内存 |
| 继续无视 `NO_PROXY`              | 本机开发间歇 502            |
| 把 agent 错误细节回传浏览器            | 信息泄漏；前端分类困难           |


### 3.6 原理小结


```plain text
浏览器（同域）
  → mode=chat  → /api/chat
  → mode=agent → /api/agent/chat（BFF）
                    → Authorization: Bearer <AGENT_INTERNAL_TOKEN>
                    → fetch(AGENT_SERVICE_URL/agent/chat)
                    → pipeUpstreamBody（client abort / 120s timeout）
                 → agent Controller 校验 Bearer
                 → streamChat → SSE
```


一句话原理：**浏览器只信任 Next；Next 才信任 agent；令牌与代理策略都留在服务端。**


## 4. 方案取舍


| 方案                           | 优点       | 缺点 / 为何不选                |
| ---------------------------- | -------- | ------------------------ |
| 边缘 Worker 直连 agent           | 少一跳      | 密钥分发与流式泵更绕；本地开发模型变了      |
| mTLS 服务间                     | 更强       | Phase 2 MVP 过重；v4 再谈正式鉴权 |
| **同域 BFF + 共享密钥 Bearer（采用）** | 实现短、演示够用 | 不是多租户登录；密钥轮换靠运维          |


口径：这是 **临时护栏**，不是 v4 正式 ACL。


## 5. 调用链


```plain text
Home mode 切换
  → DefaultChatTransport.api = /api/chat | /api/agent/chat
  → BFF：校验 Content-Length ≤ 1_048_576
  → combineAbortSignals(req.signal, timeout 120_000)
  → fetch 上游；失败 → 502/504 JSON
  → 成功 → 透传 SSE 头 + pipe body
  → agent：bearerMatchesInternalToken（生产必过）
```


## 6. 关键实现（完整核心）

> BFF 片段突出令牌 / 超时 / 泵流；生产响应还会带 `x-accel-buffering: no`、`connection: keep-alive` 等 SSE 友好头。`AGENT_UPSTREAM_TIMEOUT_MS = 120_000` 是**连接 + 整段泵流**的墙钟上限，不只是等到首字节。

### 6.2 BFF：注令牌、超时、泵流


```typescript
import { randomUUID } from "node:crypto";
import { NextResponse } from "next/server";

export const AGENT_UPSTREAM_TIMEOUT_MS = 120_000; // Agent 长任务单独 120s 墙钟上限
export const MAX_AGENT_BFF_BODY_BYTES = 1_048_576; // 防超大 messages 拖垮 BFF 内存

/** 合并多个 AbortSignal：客户端取消 + 上游超时任一触发即 abort */
export function combineAbortSignals(
  ...signals: Array<AbortSignal | undefined>
): AbortSignal | undefined {
  const list = signals.filter((s): s is AbortSignal => Boolean(s));
  if (list.length === 0) return undefined;
  if (list.length === 1) return list[0];
  if (typeof AbortSignal.any === "function") {
    return AbortSignal.any(list);
  }
  const ac = new AbortController();
  const onAbort = () => {
    if (!ac.signal.aborted) ac.abort();
  };
  for (const s of list) {
    if (s.aborted) {
      ac.abort();
      return ac.signal;
    }
    s.addEventListener("abort", onAbort, { once: true });
  }
  return ac.signal;
}

/** 创建上游超时信号；clear() 在流结束或出错时调用 */
export function createUpstreamTimeoutSignal(ms = AGENT_UPSTREAM_TIMEOUT_MS): {
  signal: AbortSignal;
  clear: () => void;
} {
  const ac = new AbortController();
  const timer = setTimeout(() => ac.abort(), ms);
  timer.unref?.();
  return { signal: ac.signal, clear: () => clearTimeout(timer) };
}

/** 解析 agent-service 基址；生产经 BFF，不暴露给浏览器 */
function agentUpstreamUrl(): string {
  const base = (
    process.env.AGENT_SERVICE_URL ||
    process.env.NEXT_PUBLIC_AGENT_SERVICE_URL ||
    "http://localhost:3002"
  ).replace(/\/$/, "");
  return `${base}/agent/chat`;
}

/** 把上游 SSE body 泵给浏览器；监听 client abort 与 timeout，及时 cancel reader */
export function pipeUpstreamBody(
  upstreamBody: ReadableStream<Uint8Array>,
  opts: {
    clientSignal: AbortSignal;
    timeout: { signal: AbortSignal; clear: () => void };
  },
): ReadableStream<Uint8Array> {
  const reader = upstreamBody.getReader();
  let cleaned = false;
  const cleanup = () => {
    if (cleaned) return;
    cleaned = true;
    opts.timeout.clear();
  };
  const cancelReader = () => {
    void reader.cancel().catch(() => {});
  };
  const onAbort = () => {
    cancelReader();
    cleanup();
  };
  if (opts.clientSignal.aborted || opts.timeout.signal.aborted) {
    cancelReader();
    cleanup();
  } else {
    opts.clientSignal.addEventListener("abort", onAbort, { once: true });
    opts.timeout.signal.addEventListener("abort", onAbort, { once: true });
  }

  return new ReadableStream<Uint8Array>({
    async pull(controller) {
      try {
        if (opts.timeout.signal.aborted) {
          cancelReader();
          cleanup();
          controller.error(new Error("agent-service 请求已取消或超时"));
          return;
        }
        if (opts.clientSignal.aborted) {
          cancelReader();
          cleanup();
          controller.close(); // 用户点停止：安静关闭，不抛错
          return;
        }
        const { done, value } = await reader.read();
        if (done) {
          cleanup();
          controller.close();
          return;
        }
        if (value) controller.enqueue(value);
      } catch (err) {
        cleanup();
        cancelReader();
        if (opts.timeout.signal.aborted) {
          controller.error(new Error("agent-service 请求已取消或超时"));
          return;
        }
        if (opts.clientSignal.aborted) {
          controller.close();
          return;
        }
        controller.error(err);
      }
    },
    cancel() {
      cancelReader();
      cleanup();
    },
  });
}

export async function POST(req: Request) {
  const requestId = randomUUID(); // 502/504 时回传，便于排障
  const upstream = agentUpstreamUrl();
  const headers = new Headers();
  const contentType = req.headers.get("content-type");
  if (contentType) headers.set("content-type", contentType);

  const token = process.env.AGENT_INTERNAL_TOKEN?.trim();
  if (token) {
    headers.set("authorization", `Bearer${token}`); // 令牌只在服务端注入，不进前端
  }

  const timeout = createUpstreamTimeoutSignal(AGENT_UPSTREAM_TIMEOUT_MS);
  const signal = combineAbortSignals(req.signal, timeout.signal);

  const contentLength = req.headers.get("content-length");
  if (contentLength) {
    const n = Number(contentLength);
    if (Number.isFinite(n) && n > MAX_AGENT_BFF_BODY_BYTES) {
      timeout.clear();
      return NextResponse.json(
        { error: `请求体过大（上限${MAX_AGENT_BFF_BODY_BYTES} 字节）` },
        { status: 413 },
      );
    }
  }

  let upstreamRes: Response;
  try {
    const bodyBuf = await req.arrayBuffer();
    if (bodyBuf.byteLength > MAX_AGENT_BFF_BODY_BYTES) {
      timeout.clear();
      return NextResponse.json(
        { error: `请求体过大（上限${MAX_AGENT_BFF_BODY_BYTES} 字节）` },
        { status: 413 },
      );
    }
    upstreamRes = await fetch(upstream, {
      method: "POST",
      headers,
      body: bodyBuf,
      signal,
    });
  } catch (err) {
    timeout.clear();
    const aborted =
      (err instanceof Error && err.name === "AbortError") ||
      req.signal.aborted ||
      timeout.signal.aborted;
    // 504=取消/超时；502=根本连不上上游
    return NextResponse.json(
      {
        error: aborted
          ? `agent-service 请求已取消或超时 (requestId:${requestId})`
          : `agent-service 不可达 (requestId:${requestId})`,
      },
      { status: aborted ? 504 : 502 },
    );
  }

  const outHeaders = new Headers();
  for (const key of ["content-type", "x-vercel-ai-ui-message-stream"] as const) {
    const v = upstreamRes.headers.get(key);
    if (v) outHeaders.set(key, v);
  }
  outHeaders.set("cache-control", "no-cache, no-transform");
  outHeaders.set("x-request-id", requestId);

  if (!upstreamRes.body) {
    timeout.clear();
    return new NextResponse(null, { status: upstreamRes.status, headers: outHeaders });
  }

  return new NextResponse(
    pipeUpstreamBody(upstreamRes.body, { clientSignal: req.signal, timeout }), // 透传 SSE 流
    { status: upstreamRes.status, headers: outHeaders },
  );
}
```


### 6.3 Agent 侧令牌（生产 fail-closed）


```typescript
import { timingSafeEqual } from "node:crypto";

/** 常量时间比较 Bearer，防计时侧信道猜前缀 */
export function bearerMatchesInternalToken(
  authorization: string | undefined,
  expected: string,
): boolean {
  const got = authorization?.match(/^Bearer\s+(.+)$/i)?.[1]?.trim();
  if (!got) return false;
  const a = Buffer.from(got, "utf8");
  const b = Buffer.from(expected, "utf8");
  if (a.length !== b.length) return false;
  return timingSafeEqual(a, b);
}

// Controller 摘要：
// 生产：无 expected 或 mismatch → 401
// 非生产：仅当配置了 AGENT_INTERNAL_TOKEN 才校验
```


### 6.4 出站代理（完整片段）


Web 与 agent-service 各有一份同构逻辑；BFF→本机必须尊重 `NO_PROXY`：


```typescript
/**
 * 让 Node fetch / undici 走 HTTP(S)_PROXY。
 * 使用 EnvHttpProxyAgent 以尊重 NO_PROXY（否则 BFF→localhost:3002 会被误代理）。
 */
import { EnvHttpProxyAgent, setGlobalDispatcher } from "undici";

export function applyOutboundProxyFromEnv(): string | null {
  const proxy =
    process.env.HTTPS_PROXY?.trim() ||
    process.env.https_proxy?.trim() ||
    process.env.HTTP_PROXY?.trim() ||
    process.env.http_proxy?.trim() ||
    "";
  if (!proxy) return null;
  setGlobalDispatcher(new EnvHttpProxyAgent());
  return proxy;
}

/** 启动日志：仅提示已启用，绝不打印 proxy URL / 凭据 */
export function logOutboundProxyStatus(proxy: string | null): void {
  if (!proxy) return;
  console.log("[web] outbound proxy enabled");
}
```


本地请保证 `NO_PROXY`（或 `no_proxy`）包含 `localhost,127.0.0.1`。

| 输入 / 条件                    | 期望                                  |
| -------------------------- | ----------------------------------- |
| UI 切到 Agent                | 网络面板请求 `/api/agent/chat`，不是 `:3002` |
| 生产未设 token                 | agent 401；BFF 上游失败可观测               |

| 用户停止生成                     | 上游被取消；不再长时间空转                       |
| Clash + 缺 `NO_PROXY`       | 易 502；补上后恢复（对照第 2 篇）                |
| body > 1MB                 | 413                                 |


## 9. 诚实边界

- **不是**登录多租户；共享密钥谁拿到谁能打 agent。
- `NEXT_PUBLIC_AGENT_SERVICE_URL` 仍可作为上游基址回退，但**生产路径默认经 BFF**；不要把内部令牌做成 public。
- 120s 超时是经验值；超长调研可能触顶。
- 正式 ACL / Docker 网络策略属 v4。

## 10. 收束

1. Chat 与 Agent 是产品分流，不是同一个 API 硬撑两种 SLA。
2. BFF 让浏览器永远不拿内部令牌、不直连 agent 端口。
3. Abort 与超时必须贯穿 BFF→agent，否则「停止」只是 UI 假象。
4. `EnvHttpProxyAgent` + `NO_PROXY` 是本机可演示的必要条件。
5. 这是 MVP 护栏，不是生产级身份体系。
