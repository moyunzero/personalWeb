## 0. 背景


**流式输出（streaming）**：模型不是一次返回整篇文章，而是像打字一样不断推出小片段（delta）。浏览器边收边渲染，首字更快。


**SSE（Server-Sent Events）**：一种「服务器单向推送」的 HTTP 用法。连接保持打开，一行行 `data: {...}` 推过来。本项目用它推正文增量，也推「步骤开始了 / 结束了」这类自定义事件。


**TransformStream**：可以理解为水管上的过滤器——上游流出的事件经过去重、隐藏中间段、消毒后再给浏览器。出问题往往在这些过滤器，而不在「会不会调度」。


**BFF（Backend for Frontend）**：浏览器只访问同源的 Next.js 接口（如 `/api/agent/chat`），由服务器再去请求真正的 `agent-service`。好处：内部令牌、端口、CORS 细节不暴露给浏览器。


**HTTP 代理 /** **`NO_PROXY`**：开发时常用 Clash 等工具让出站请求走代理。若代理规则把 `localhost` 也拐走，本机服务会「明明活着却连不上」。`NO_PROXY=localhost,127.0.0.1` 的意思是：这些地址请直连，别进代理。


**闲聊短路**：识别「你好」这类寒暄后，不启动多专科图，直接回一句固定礼貌话——省时间、省钱。


**HTTP 状态码脚注**：本篇常提 **502**（网关/上游连不上）与 **NETWORK**（前端把传输失败归成一类错误卡）。本机 agent `/health` 已 200 却 BFF 502，多半是出站代理拐走了 `localhost`，不是「agent 挂了」。


**abort（取消）**：用户点停止或超时后，浏览器关掉请求；BFF 要把这个信号转给上游，否则 agent 还在烧配额。


**孤儿 tool-output**：流式协议里「工具调用开始」与「工具结果」成对出现；若中间取消，可能只剩结果事件——管线要丢掉这种孤儿，否则前端解析会乱。

## 1. 开场矛盾


编排跑通之后，用户看见的第一批问题往往不是「会不会调度」，而是：

1. **字翻倍**：同一句正文闪两遍，像卡顿回放。
2. **报告头粘连**：屏幕上出现 `知识库未找到足够依据# xx手册：情报简报`——miss 叙述和标题焊在一起。
3. **闲聊空白**：Agent 模式回「你好」只有步骤「已短路」，气泡没有正文。
4. **整页 NETWORK**：本机 agent 明明 `/health` 200，BFF 却 502——Clash 把 `localhost:3002` 送进了代理。

这些都不是「再加点 prompt」能修好的。它们落在 **SSE 变换管线、短路写回路径、Node 出站代理** 三条工程缝上。


## 2. 本篇目标


讲清 Agent 对外可读的三块胶水：**流式 TransformStream 消毒**、**闲聊短路必须写出可见文本**、**BFF +** **`EnvHttpProxyAgent`** **尊重** **`NO_PROXY`**。


## 3. 机制


### 3.1 总览


| 层/部件                          | 做什么                             | 代价                   | 代码入口     |
| ----------------------------- | ------------------------------- | -------------------- | -------- |
| `deduplicateTextDeltas`       | 去合并流伪影重复 delta                  | 可能误伤「合法连续相同字」极短 case | §6.1     |
| `suppressIntermediateText`    | 终稿前藏专科中间话；解锁丢非报告持有段             | 实现状态机稍绕              | §6.2     |
| `sanitizeUserFacingAgentText` | 剥 `KB_SEARCH_STATUS` 等协议串；断标题粘连 | 规则要跟协议一起演进           | 概念见 §3.5 |
| `isAgentChitchat` + 短回复直写     | 寒暄不进 Supervisor                 | 正则覆盖有限               | §6.3     |
| `EnvHttpProxyAgent`           | 出站走代理且尊重 `NO_PROXY`             | 依赖 undici 实验 API     | §6.4     |


### 3.2 为什么要这么做

- **流式伪影**：LangGraph → UIMessage 合并时，同一 `text-delta` 可能被 enqueue 两次；用户感知是「产品坏了」，不是「框架细节」。
- **中间叙述泄漏**：Retriever miss 一句若先解锁，再跟 Editor 标题，前端 Markdown 会把两段拼成灾难标题。
- **短路若只改图状态**：步骤事件有了，AI SDK 气泡没文本——验收直接判挂。
- **全局** **`ProxyAgent(proxyUrl)`**：国内开发常开系统代理；不认 `NO_PROXY` 时，BFF→本机 agent 全军覆没。

### 3.3 优势


| 对比对象              | 本方案优势                      |
| ----------------- | -------------------------- |
| 前端事后正则洗正文         | 服务端一次清洗，Chat/Agent 客户端行为一致 |
| 关闭所有中间 text       | 步骤仍可推；只压「面向用户的段落」          |
| 闲聊也走完整 Supervisor | 短路省整图；有固定中文回复              |
| 强制用户关 Clash       | 代理可保留给出站；环回靠 `NO_PROXY`    |


### 3.4 不做会怎么样


| 若取消…                          | 会发生什么                                    |
| ----------------------------- | ---------------------------------------- |
| 取消无 seq 连续去重                  | 字符级 / 片语级翻倍回归                            |
| 取消首次解锁 `dropNonReport`        | `依据# 标题` 粘连回归                            |
| 取消协议串消毒                       | 用户看见 `KB_SEARCH_STATUS: NO_RELEVANT_HIT` |
| 短路不写可见 text                   | 步骤完成、气泡空                                 |
| 继续用无视 `NO_PROXY` 的 ProxyAgent | 本机 BFF 间歇 502 NETWORK                    |


### 3.5 原理小结（数据流）


```plain text
agent-service stream
  → stripMergedStart
  → dropOrphanToolOutputs
  → deduplicateTextDeltas
  → suppressIntermediateText（多步时藏到 editor）
  → dropHandoffNoiseText + sanitizeUserFacingAgentText
  → pipeUIMessageStreamToResponse
       ↑
浏览器 → Next BFF（abort 转发）→ fetch(agent)
              ↑
     EnvHttpProxyAgent（NO_PROXY 含 localhost）
```


一句话原理：**编排负责对；管线负责好看；代理负责连得上。**


## 4. 方案取舍


| 方案                                             | 优点             | 缺点 / 为何不选                              |
| ---------------------------------------------- | -------------- | -------------------------------------- |
| 只改前端渲染去重                                       | 不动服务端          | 每个客户端重做；协议串仍可能进历史                      |
| WebSocket 替代 SSE                               | 双向             | 本产品是单向 token 流；AI SDK UIMessage 已绑 SSE |
| 系统级强制直连 localhost                              | 省代码            | 无法约束所有 Node 子进程；文档负担大                  |
| **TransformStream 管线 + EnvHttpProxyAgent（采用）** | 与 AI SDK 流模型契合 | 要认真测 abort / 孤儿 tool-output            |


## 5. 调用链


```plain text
「你好」→ resolveAgentRoute(userText)==="short"
  → 不编译协作图；服务层 buildShortReplyMessages → 直接写 text 事件
  → 轨迹 route=short

多步报告（清单含 editor）→ hideUntilEditor
  → 专科 text 被 suppress 持有
  → Sequential：editor 节点 updates 置 textGate.open=true
     （或 tracker 显示 editor 已激活/已跑过）
  → 丢非报告持有段（报告判定：Markdown 标题开头或 ≥400 字）→ 终稿流出
  → sanitize 去掉协议串、断开「依据#」粘连

浏览器 POST /api/agent/chat
  → BFF 注入内部令牌、转发 AbortSignal
  → undici 出站：外网走代理，localhost 直连 :3002
```


## 6. 关键实现


### 6.1 文本 delta 去重


```typescript
/**
 * 合并流可能重复 enqueue 同一 text-delta。
 * - 有 seq：按 id 单调序号去重
 * - 无 seq：连续相同 id+delta 视为合并伪影丢弃
 */
export function deduplicateTextDeltas(): TransformStream<any, any> {
  const lastSeqById = new Map<string, number>();
  let lastContentKey = "";
  return new TransformStream({
    transform(chunk, controller) {
      const obj = chunk as { type?: string; id?: string; delta?: string; seq?: number };
      if (obj?.type === "text-delta") {
        const id = obj.id ?? "_";
        if (typeof obj.seq === "number" && Number.isFinite(obj.seq)) {
          // 有 seq：同 id 下序号不递增则视为重复 enqueue，直接丢
          const prev = lastSeqById.get(id);
          if (prev !== undefined && obj.seq <= prev) return;
          lastSeqById.set(id, obj.seq);
          lastContentKey = "";
        } else {
          // 无 seq：连续相同 id+delta 视为合并伪影
          const key = `${id}:${obj.delta ?? ""}`;
          if (key === lastContentKey) return;
          lastContentKey = key;
        }
      } else {
        lastContentKey = "";
      }
      controller.enqueue(chunk);
    },
  });
}
```


### 6.2 隐藏中间叙述，解锁时丢掉非报告段


```typescript
declare function isReportLikeHeldText(chunks: any[]): boolean;

/**
 * hideUntilEditor：锁定期间只保留「最后一段」完整 text；
 * 首次解锁：若持有段不像报告，直接丢弃，避免与标题粘连。
 */
export function suppressIntermediateText(opts: {
  hideUntilEditor: boolean;
  textUnlocked: () => boolean;
  unlockText?: () => void;
}): TransformStream<any, any> {
  let pending: any[] = []; // 锁定期间正在拼的一段 text
  let lastComplete: any[] | null = null; // 最近一段完整的 start→delta→end
  let wasUnlocked = !opts.hideUntilEditor;

  const flushHeld = (
    controller: TransformStreamDefaultController<any>,
    optsFlush: { dropNonReport: boolean },
  ) => {
    if (lastComplete) {
      // 首次解锁：若持有段不像报告，丢弃，避免 miss 叙述与标题粘连
      if (!optsFlush.dropNonReport || isReportLikeHeldText(lastComplete)) {
        for (const c of lastComplete) controller.enqueue(c);
      }
      lastComplete = null;
    }
    for (const c of pending) controller.enqueue(c);
    pending = [];
  };

  return new TransformStream({
    transform(chunk, controller) {
      const obj = chunk as { type?: string; toolName?: string };
      // Supervisor 递话筒给 editor 时提前解锁（开放模式）
      if (
        opts.hideUntilEditor &&
        obj?.type === "tool-input-start" &&
        /transfer_to_editor/i.test(obj.toolName ?? "")
      ) {
        pending = [];
        lastComplete = null;
        opts.unlockText?.();
      }

      const unlocked = !opts.hideUntilEditor || opts.textUnlocked();
      if (unlocked) {
        const firstUnlock = !wasUnlocked;
        wasUnlocked = true;
        flushHeld(controller, { dropNonReport: firstUnlock });
        controller.enqueue(chunk);
        return;
      }

      // 锁定：只缓冲 text 事件，步骤/tool 等非正文仍放行
      wasUnlocked = false;
      const t = obj?.type;
      if (t === "text-start") {
        pending = [chunk];
        return;
      }
      if (t === "text-delta" && pending.length > 0) {
        pending.push(chunk);
        return;
      }
      if (t === "text-end" && pending.length > 0) {
        pending.push(chunk);
        lastComplete = pending; // 整段收齐后再决定是否放出
        pending = [];
        return;
      }
      if (t === "text-start" || t === "text-delta" || t === "text-end") {
        return;
      }
      controller.enqueue(chunk);
    },
    flush(controller) {
      flushHeld(controller, { dropNonReport: false });
    },
  });
}
```


配套：面向用户的 sanitize 会把 `KB_SEARCH_STATUS: NO_RELEVANT_HIT` 收成自然语言，并在「依据」与 `# 标题` 之间强制换行——专门对付粘连。


### 6.3 闲聊短路


```typescript
import { AIMessage, type BaseMessage } from "@langchain/core/messages";

const GREETING_PHRASES = new Set([
  "你好", "您好", "嗨", "hi", "hello", "hey",
  "在吗", "在不在", "早上好", "晚上好", "午安",
  "拜拜", "再见", "谢谢", "好的", "ok", "okay",
]);

const CASUAL_CHITCHAT = [
  /^今天天气怎么样$/,
  /^天气怎么样$/,
  /^你是谁$/,
  /^你叫什么$/,
  /^在干嘛$/,
  /^怎么样$/,
];

const TRAILING_PUNCTUATION = /^[\s!！?？。,，~～]+|[\s!！?？。,，~～]+$/g;
const MIN_MEANINGFUL_LENGTH = 2;

function codePointLength(value: string): number {
  return Array.from(value).length; // 按 Unicode 码点计长，emoji 不会误算
}

function normalize(text: string): string {
  return text.trim().replace(TRAILING_PUNCTUATION, "").toLowerCase();
}

/** 命中则走短路：不编译多专科图，直接固定回复 */
export function isAgentChitchat(text: string): boolean {
  const trimmed = text.trim();
  if (codePointLength(trimmed) < MIN_MEANINGFUL_LENGTH) return true;
  const core = normalize(text);
  if (!core) return true;
  if (GREETING_PHRASES.has(core)) return true;
  if (CASUAL_CHITCHAT.some((re) => re.test(core))) return true;
  return false;
}

/** 短路分支必须产出可见正文（见 §6.3 实现要点） */
export function buildShortReplyMessages(text: string): BaseMessage[] {
  const core = normalize(text);
  let content: string;
  if (!core || codePointLength(core) < MIN_MEANINGFUL_LENGTH) {
    content = "你好！有什么我可以帮你的吗？可以直接问知识库或调研类问题。";
  } else if (GREETING_PHRASES.has(core)) {
    content = "你好！我是企业知识库助手。有什么问题可以帮你？";
  } else if (/天气/.test(core)) {
    content =
      "这是闲聊短路回复：若要查实时天气或做深度调研，请用更具体的任务描述（例如公司政策、报告分析）。";
  } else {
    content = "收到。若需要知识库检索或多步调研，请用一两句说清目标，我再调度专科助手。";
  }
  return [new AIMessage(content)];
}
```


实现要点：短路分支必须把上述字符串写成 **UIMessage 的 text-start / text-delta / text-end**（或等价路径），不能只更新 LangGraph messages 却绕过面向浏览器的写手。


### 6.4 出站代理尊重 NO_PROXY


```typescript
import { EnvHttpProxyAgent, setGlobalDispatcher } from "undici";

/** 切勿再用「只吃 proxy URL、忽略 NO_PROXY」的 ProxyAgent 包环回。 */
export function applyOutboundProxyFromEnv(): string | null {
  const proxy =
    process.env.HTTPS_PROXY?.trim() ||
    process.env.https_proxy?.trim() ||
    process.env.HTTP_PROXY?.trim() ||
    process.env.http_proxy?.trim() ||
    "";
  if (!proxy) return null;
  // EnvHttpProxyAgent 会读 NO_PROXY，localhost 直连，避免 BFF→本机 agent 502
  setGlobalDispatcher(new EnvHttpProxyAgent());
  return proxy;
}

export function logOutboundProxyStatus(proxy: string | null): void {
  if (!proxy) return;
  console.log("[web] outbound proxy enabled"); // 绝不打印 URL / 凭据
}
```


请在环境里显式配置 `NO_PROXY=localhost,127.0.0.1,::1`（以及你的内网段）。BFF 还要把浏览器 abort 转给上游，避免用户点停止后 agent 仍烧配额。

## 8. 如何验证


| 输入 / 条件                                   | 期望                               |
| ----------------------------------------- | -------------------------------- |
| Agent「你好」                                 | 有可见中文回复；轨迹 `route=short`         |
| 多步报告                                      | 终稿前不刷 Retriever 长叙述；无 `依据#` 粘连   |
| 故意制造重复 delta（单测）                          | `deduplicateTextDeltas` 丢掉连续相同片  |
| `HTTPS_PROXY` 开着 + `NO_PROXY` 含 localhost | `POST /api/agent/chat` → 200 SSE |
| 去掉 NO_PROXY（对照）                           | 本机 BFF 易 502（用于证明根因）             |


## 9. 诚实边界

- 去重策略是启发式，不是密码学幂等。
- 短路词表覆盖「常见中文寒暄」，不是意图分类器。
- `EnvHttpProxyAgent` 在 undici 中仍带 experimental 警告——行为以当前 Node / undici 为准。
- 本阶段没有把「流式质量」做成自动 KPI；靠单测 + 浏览器复测。

## 10. 收束

1. 用户看见的故障，多半在 SSE 与代理，不在「会不会选 Researcher」。
2. 去重 + 抑制中间段 + sanitize，把多 Agent 脏流收成可读报告。
3. 短路必须写正文。
4. 代理必须放过环回，否则 Agent 模式伪死。
