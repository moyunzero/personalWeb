## Minor

### 🟡 Web derivatives must be committed in the same commit, `public/threejs-assets/web/*`
**Problem**: All 16 runtime assets are still untracked. If the author commits code without `git add public/threejs-assets/web/`, the branch is internally inconsistent.
**Why it matters**: A commit with the island but without the derivatives will fail `yarn build` on CI (the new gate). That is the intended fail-safe, not a silent break, but it is still a red CI run.
**Suggested fix**: Stage and commit `public/threejs-assets/web/` together with the source/spec changes; confirm `git status` is clean afterward. (Total is 2.6 MB, well under the 8 MB budget.)

### 🟡 Per-frame allocations in the render loop, `CosmicStarfieldIsland.tsx:137-143`
**Problem**: Each rAF tick allocates: `systemStateAt` (new array of 8 objects), `new Set(SECTION_FOCUS[section])`, and `focusPoseFor` (default arg builds a fresh `Map` of 8 entries every call — `solarSystemModel.ts:386`).
**Why it matters**: On a decorative always-on background at 60 fps this is steady GC pressure, working against the AC-7 Lighthouse/LCP budget on mid/low-end devices the spec explicitly worries about.
**Suggested fix**: Hoist the highlight `Set` (rebuild only on section change), reuse a scratch states array, and pass a prebuilt `byId` map into `focusPoseFor` rather than relying on the allocating default parameter.

### 🟡 Pointer/drag integration is only source-grepped, not behaviorally tested, `CosmicStarfieldIsland.tsx:203-296`
**Problem**: The extracted pure helpers (`dampHalfLife`, `clampZoomFactor`, `reseedLastPointerAfterPinch`, `isCosmosExploreTarget`) are well covered, but the island's own `onPointerDown/Move/Up` state machine — pending-pointer threshold, pinch distance tracking, `activePointers` bookkeeping — is verified only by regex matches on the source and by E2E that never drives an actual drag/pinch or a section-focus switch.
**Why it matters**: `TESTS = configured`; this branching interaction logic is exactly where regressions hide (e.g. a future edit to the `activePointers.size === 2` guard). Grep tests pass even when behavior is wrong.
**Suggested fix**: Extract the drag/pinch reducer into a testable pure function (input: pointer events + state → new state) and unit-test threshold crossing, pinch zoom, and reseed, or add a Playwright test that performs a drag and asserts the canvas responds. Not blocking given the model math and helpers are covered.

## Nits

- ⚪ `solarSystemScene.ts:181-322` — textures load sequentially (`await loadTexture` inside the planet loop and for each earth/venus/saturn extra), serializing ~16 network fetches and lengthening time-to-fade-in. Consider `Promise.all` per planet or batch. Poster covers the gap, so cosmetic.
- ⚪ `prepare-threejs-assets.mjs:57-76` — the RGBE header advertises `FORMAT=32-bit_rle_rgbe` but `writeRGBE` emits flat (non-RLE) scanlines. Three's `HDRLoader` reads it fine (per-scanline detection), but the header is misleading; either RLE-encode or label it accurately.
- ⚪ `solarSystemModel.ts:389-400` — `focusPoseFor` computes `sx/sy/sz/maxR` for every section including `home`, then discards them for `home` (returns a fixed pose at line 402-410). Minor dead work; early-return for `home` first.
- ⚪ `AGENTS.md` / `skills-lock.json` — `sprites-and-images` skill link was dropped from `AGENTS.md` but I did not see it removed from `skills-lock.json`; confirm the lock and the doc agree.
